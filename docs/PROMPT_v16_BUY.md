## PROMPT

너는 BOSUNG VINA(베트남 색연필 공장) ERP를 유지보수하는 시니어 개발자다. 기능과 숫자 정의는 그대로 두고, 아래를 **15차(v1.10.x) 위에서** 한다. 이름 · 글자를 짐작해서 쓰지 말고, 모르면 사용자에게 묻는다.

### 1. 사용자 요청 (원문, 2026-10-21 · 첨부 자재구매 파일 `261021 자재구매.xlsx`)
> 안전재고 참고해주고 여기에있는 품목만 원부자재 탬안에 따로볼수있게 버튼을 만들어주고 이품목만 따로 주문할수있게 안에 표 형태를 유지해줘. 이품목은 해외에서 주문하는거기때문에 리드타임이있어서 따로 관리해야한다.

정리:
- 안전재고 = 파일의 Safety stock.
- 원부자재 재고 메뉴 안에 이 파일의 품목만 따로 보는 **버튼**.
- 그 안에서 이 품목만 **따로 주문** — 표는 **파일과 같은 모양**.
- 해외에서 주문 → **리드타임** 이 있으므로 따로 관리.

### 2. 자료 (자재구매 파일)
- 시트 `Oder Korea` (파일 그대로의 이름): 2행 `Date :` 옆 칸 = 파일 날짜, 4행 머리 — `Category · Item Code · Item Name · Item Name Kr · Safety stock · Unit · Inventory · 입고예정 · <주문일> · <주문일> · Total · kg/month · ea/month · Max · Min · Average` (주문일 머리 칸은 엑셀 날짜 숫자), 5행 = 엑셀 표 자체의 머리 (`열3 · 열2 · 열1 · 3일 · Column…`), 6행부터 품목.
- `Total` = Inventory + 입고예정 + 주문일 칸 (수식). kg/month · ea/month = 옆 표(출고 피벗, kg 와 개 = 포대 · 통 수)에서 찾아온 값, Max · Min · Average = 월별 출고 (다른 시트).
- 다른 시트 (월별 사용량 · 지난해 출고 장부 · 메모 · Oil Order) 는 읽지 않는다.
- 이 PC: 81줄 · 코드 78 (R-015 · R-016 · R-027P 가 두 번 — R-015 · R-016 은 Pigment 와 BIC Pigment 의 안전재고가 다름), ERP 품목에 76 (R-031A · R-300C 없음), 단위가 다른 것 R-380 (파일 kg · ERP ROLL), `ea` = PCS · `KGS` = kg. 주문일 칸 2026-10-21 에 7품목.

### 3. 확정한 규칙
1. **인식** (`XL.addDetector('buy_list')`): 머리 줄에 Item Code · Safety stock · Inventory. 주문일 칸 = 입고예정(없으면 Inventory) 다음 ~ Total 앞의 날짜 머리. 파일 날짜 = `Date :` 옆 칸 → 파일 이름 → 오늘. 코드 칸이 `Item Code` 인 줄(엑셀 표 머리)은 건너뜀. 같은 코드가 두 번이면 **첫 줄** (미리보기에 두 줄의 구분 · 안전재고를 보인다).
2. **품목** (작업 `buy_items`): 해외 주문 표시 `buy`, 구분 `buy_cat`, 한글 품명 `name_kr`, 파일 순서 `buy_ord`, 파일 단위 `buy_unit`, 파일 재고 `buy_inv` · 날짜 `buy_inv_date`.
   - 안전재고: 파일 단위가 ERP 단위와 같으면 품목 `safety` (원부자재 재고의 상태 · 경고에도 쓰임), 다르면 `buy_safety` (해외 주문 표에서만, 파일 단위).
   - ERP 에 없는 코드 → 새 품목 (이름 · 한글 품명 · 단위는 파일 그대로, kg → 원재료 RM, 그 밖 → 부자재 SM, `src: 'buy'`).
   - 이 파일에 없는 해외 주문 품목은 표시를 끈다 (파일 = 목록).
3. **주문** (표 `buy_orders`, 작업 `buy_orders`): 주문일 칸 → 그 날 주문 (입고 대기 `status: 'open'`), 입고예정 칸 → `kind: 'inc'` 한 줄 (주문일 없이 들어올 수량, 날짜 = 파일 날짜).
   - 다시 올리면 **파일에 있는 주문일 · 품목의 입고 대기 주문은 파일 값** (빈 칸이면 지움), 입고예정도 파일 값. 입고 완료(`status: 'recv'`)와 파일에 없는 날짜의 주문(ERP 에서 넣은 것)은 그대로.
4. **화면**: 원부자재 재고 → **해외 주문** 탭 (`ERP.buyTab`), 원부자재 재고 탭의 **"해외 주문 품목만 N"** 버튼, 원부자재 재고 표에 "해외 주문" 표시.
   - 칸 순서 = 파일: 구분 · 품목코드 · 품명 · 품명 (한글) · 안전재고 · 단위 · 재고 · 입고예정 · 주문일들 (최근이 앞) · 합계 · kg/월 · ea/월 · 최대 · 최소 · 평균, 뒤에 리드타임 (일) · 도착 예정 · 상태 · 권장 주문량. 줄 순서 = 파일 순서. 칸 머리에 마우스를 올리면 파일의 영어 머리.
   - 재고 = ERP 원부자재 재고 (창고 + 공장), 단위가 다르면 개당 kg 로 바꾼다 (못 바꾸면 –). 파일 재고와 다르면 그 아래에 "파일 …".
   - 합계 = 재고 + 입고예정 + 입고 대기 주문 (= 파일의 Total).
   - 월 사용량 = 창고 출고 (OUT · 창고 → 공장 이동) 월별, 지난 12달 (창고 기준일 뒤) ~ 지난달. kg/월 · ea/월 = 지난달 (kg 품목의 ea = kg ÷ 개당 kg, 개 품목은 kg/월 을 비움), 최대 · 최소 · 평균 = 그 달들.
   - 리드타임 = 품목별 `lead_days` 또는 기본값 (설정 `buyLead`, 처음엔 비어 있음). 도착 예정 = 주문일 + 리드타임 (입고예정 칸은 직접 넣은 `eta` 만), 지나면 빨간 글자.
   - 상태: 안전재고가 없으면 "안전재고 없음", **합계 − 리드타임 동안 쓸 양 (월 평균 ÷ 30 × 리드타임) < 안전재고 → 주문 필요**, 아니면 충분. 권장 주문량 = 안전재고 + 리드타임 동안 쓸 양 − 합계 (kg 품목은 개당 kg 단위로 올림, 그 밖은 정수로 올림).
   - 주문: 주문일 칸 · 입고예정 칸에 수량을 넣으면 바로 저장 (빈 칸 · 0 = 지움, 그 줄만 다시 계산), [+ 주문 칸] (날짜), [권장 주문량 넣기] (가장 최근 새 칸, 그 날 주문이 없는 주문 필요 품목), 칸 머리 [입고 완료] · [×], 칸마다 ✓ (입고 완료 ↔ 입고 대기). **입고 완료는 합계에서 빼기만** — 재고는 창고 입출고장 · 수불로 들어온다 (두 번 세지 않게).
   - 엑셀 (같은 표): 머리 글자도 파일 그대로 → 다시 올리면 자재구매 파일로 인식.
5. 발주 · 안전재고의 "발주 필요 목록"은 해외 주문 품목을 빼고 안내 (그중 주문 필요 수 · 해외 주문 탭 링크). AI 비서 `reorder` 도구는 해외 주문 품목 줄에 `overseas: true` · `lead_days`.
6. (같이 고침) 발주 필요 목록의 권장 발주량 · 정렬 — 12차에 주석 안으로 들어가 계산되지 않던 것 (`.map(need)` · `.sort`).

### 4. 코드
- `app/js/buy.js` (새 파일, `index.html` 에서 p_stock.js 다음): 인식기 · 작업 2개 (`applyItems` · `planOrders`/`applyOrders`), 계산 `ERP.buy` (`lead` · `leadOf` · `items` · `toBuy` · `safetyOf` · `usage` · `months` · `rows`), 탭 `ERP.buyTab`.
- `schema.js`: 품목 칸 (`buy` · `buy_cat` · `name_kr` · `buy_unit` · `buy_safety` · `buy_ord` · `lead_days` · `buy_inv` · `buy_inv_date`), 새 표 `buy_orders` (nat: date · code · kind).
- `p_stock.js`: 원부자재 재고 메뉴 탭 `buy`, "해외 주문 품목만" 버튼 · 표시, 발주 목록에서 빼기 + 권장 발주량 고침.
- `p_data.js`: 자료 올리기 안내 카드 "자재구매 (해외 주문 품목)", 반영 결과 "해외 주문 보기".
- `assistant_tools.js`: reorder 의 overseas.

### 5. 지켜야 할 것
- 파일 = 해외 주문 품목 목록 · 안전재고 · 주문의 기준 (다시 올리면 그 값). ERP 재고는 창고 입출고장 · 수불 — 해외 주문 탭은 재고를 바꾸지 않는다.
- 새 품목 이름 · 구분은 파일 그대로 (짐작하지 않음). 리드타임 기본값은 사용자가 정한다 (비어 있으면 리드타임 없이 계산).
- 새 화면은 휴대폰 폭에서 옆으로 밀리지 않게 (표만 `.tbl-wrap` 안에서 옆으로).

### 8. 1.11.1 — 재고를 자재구매 파일의 재고(H열 Inventory)에 맞춤 (2026-10-21)
- 사용자: "자재구매 파일의 재고가 맞다. ERP 재고를 파일에 맞춰줘." → (어느 칸인지 확인) "H열(Inventory) 값이 맞다."
- 규칙: 자재구매 파일을 올리면 세 번째 작업 **"재고를 파일 재고(Inventory)에 맞춤"** (`buy_stock`, 기본 반영) — 품목마다 **파일 날짜의 ERP 재고와 H열 값의 차이만큼 조정**(`stock_tx` `kind: 'ADJ'`, `to_scope: 'WH'`, `src: 'buy'`, 용도 "자재구매 파일 재고 맞춤", 비고 = 파일 이름).
  - H열이 빈 품목은 그대로. 단위가 다르면 개당 kg 로 바꿔서 (못 바꾸면 그대로, 미리보기에 표시). ERP 에 없던 품목은 재고 0 에서 맞춤.
  - 같은 날짜의 파일을 다시 올리면 **그 날의 이 조정만 빼고 다시 계산**해 바꾼다 (늘지 않음). 다른 날짜의 파일은 그 날짜에 새 조정 (예전 조정은 기록으로 남음).
  - 창고 입출고장을 다시 올려도 이 조정은 그대로 (`src: 'wh'` 만 바뀜) — 창고 입출고장을 고쳐 올린 뒤에는 자재구매 파일을 다시 올리면 그 날짜에 다시 맞춰진다.
- 이 PC: 22 품목 조정 (예: R-011 100 → 250 kg, R-204 3,654,000 → 6,678,000, R-380 16 → 16.8 ROLL = 1,050 kg), 55 품목은 이미 같음, R-300C 는 H열이 비어 그대로 → 78 품목 모두 ERP 재고 = H열.
