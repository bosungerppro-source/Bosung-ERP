## 1. 무엇이 잘못됐나 (실제 자료 사본, 2026-11-06)

1. **서로 다른 물건을 한 숫자로 더함.** 17차 (1.12.0) 피벗 표는 공정을 여러 개 고르면 품목군 한 칸에 더했다.
   - 저장된 표 "리필 성형 · 조립 · 사출 재고" 의 Mini 7,928,886 = 조립품 9,779,999 + 심 2,627,048 + 사출 부품 −4,478,161.
   - 공정 하나만 골라도 사출은 배럴 · 노즈콘 · 홀더 · 스푼을 한 칸에 더했다.
2. **사출 생산이 묶음 이름으로 들어감.** 사출 일보는 Barrel · Holder · Spoon · Nose cone 으로 들어오고 (10-27 에 같은 이름의 품목군 없는 품목이 생김), 조립 BOM 은 MH · BP · RSP · MS 같은 개별 부품을 뺀다 → 묶음은 +, 개별은 −.
3. **종이 권취가 만든 Glass 가 조립 재고로 보임.** 공정을 ERP CODE 단계로 정했기 때문 (WIP = 조립).
4. **포장 재고는 지금 자료로 셀 수 없음.** 포장 일보에 박스 수가 없고, 박스 품목에 CT당 set 이 없으며, 출고가 재고에서 빠지지 않는다.

## 2. 원칙 (지킬 것)

1. 현장 재고 = 공정마다 "그 공정이 만들어 놓고 다음 공정이 아직 가져가지 않은 것".
2. 품목 하나는 공정 하나에만 들어간다.
3. **더하기는 같은 구분 · 같은 단위 안에서만.** 공정끼리 · 구분끼리 (배럴 + 스푼) · 단위끼리 (SET + CT) 는 더하지 않는다.
4. 자료가 적히는 수준으로 보여 준다: 사출 = 구분 × 품목군 (일보에 색이 없음), 나머지는 품목 (색) 까지.
5. 장부 숫자는 숨기지 않는다: 마이너스 · 못 넣은 일보 · BOM 없는 생산 · 단위를 못 바꾼 품목은 그 카드에 경고로.
6. **공정 · 구분 · 품목군은 ERP CODE 를 쓰지 않는다** (사용자 "erp코드는 무시하고 너가 만들어"). ECOUNT BOM 줄의 비고도 쓰지 않는다.
7. 재고 계산 (INV.rows 의 숫자) 은 바꾸지 않는다. 묶어서 보여 주는 방법만 바뀐다.

## 3. 현장 분류 (`INV.floorClass`, 품목코드 → { proc, kind, line, multi, src })

- **공정** — 앞의 것이 이긴다.
  1. 품목 기준 정보 '생산 공정' (`items.proc`, 사람)
  2. 단위가 SET · CT → 포장 (마니라 세트 · 박스)
  3. 생산 일보 (전체 기간, 코드 · 코드 연결로 품목에 닿는 줄) 에서 가장 많이 만든 공정
  4. 공장 자료의 역할: 색상별 BOM (`bom`: color_code = 조립품 · refill_code = 심 · nose_code = 노즈콘 · barrel_code = 배럴 · holder · spoon) · 리필 규격 (`refill_specs.erp_code` = 심) · 품목 구성 (`item_bom.item` = 박스)
  5. 반제품 목록 CL-1 · CL-2 · CL-3 (Barrel · Nose cone · Holder · Spoon · Refill 낱말)
  6. BOM 구조 (`bom_lines` 부모 · 자식만): 부모가 조립품 · 권취품이면 부품 (이름이 심이면 심), 부모가 사출 부품이면 같은 부품, 부모가 포장이면 조립품, 자식만 있으면 조립품
  7. 이름 낱말 (HOLDER · PLUG · SPOON · NOSE · BARREL · REFILL · TUBE …)
  8. 그래도 없으면 '분류 안 됨' 카드 — '생산 공정' 을 넣으면 그 공정 카드로 간다
- **구분**: 사출 = 배럴 · 노즈콘 · 홀더 · 스푼 · 그 밖의 부품 (사람 → 공장 자료 → 반제품 목록 → 사출 일보 부품 이름 → 이름), 리필 = 심, 조립 = 조립품 · 조립 중간품 (다른 조립품의 자식), 권취 = 권취품, 포장 = 세트 · 박스. 사람이 `items.fkind` 로 정할 수 있다.
- **품목군**: 사람 (`items.fline`) → 공장 자료 품목군 (색상별 BOM division · 리필 규격 구분 · 품목 구성 품목군) → 반제품 목록 CL (CL-3 → 2 → 1) → 생산 일보 품목군 → BOM 부모 · 자식 → 이름.
  - 글 → 품목군: `INV.floorLine` (`ERP.normDiv` → `INV.lineOfDiv` → 낱말). **Peel = Glass** (종이 권취 연필, 1.13.13).
  - 사출 일보가 묶음 이름으로 여러 품목군을 만든 품목은 `multi` — 생산 입고를 일보 줄의 품목군으로 나눈다 (`INV.floorSplit`), 나머지 (실사 · 입출고 · 조정) 는 '품목군 미지정'.

## 4. 화면 — 현장 재고 (`app/js/pivot.js` `ERP.floorPivot`)

- 위: **공정 카드** (순서 고정) 사출 · 리필 성형 · 조립 · 종이 권취 · 포장 (+ 분류 안 된 품목, 있을 때만).

  | 카드 | 줄 | 칸 | 합계 |
  |---|---|---|---|
  | 사출 | 구분 | 품목군 | 줄마다 (맨 아래 합계 없음) |
  | 리필 성형 · 종이 권취 | 품목군 | 현재 재고 | 맨 아래 |
  | 조립 · 포장 | 품목군 | 구분 (단위마다 칸, 포장은 세트 (SET) · 박스 (CT)) | 칸마다 맨 아래 (칸끼리는 안 더함) |
  | 분류 안 된 품목 | 품목 | 현재 재고 | 없음 |

- 카드 아래: 단위 · 실사 기준일 · 마지막 일보 · 경고 (마이너스 → 아래 표, 나머지 → 생산 반영). 칸 설명 = 실사 + 생산 − 사용 ± 기타 = 현재.
- 카드 [설정]: 줄 (품목군까지 · 품목까지) · 품목군 거르기 · 범위 (창고+공장 · 창고 · 공장) · 재고 0 줄 · 카드 숨기기 (아래 줄의 [보이기]). 공정 고르기 · 표 추가 없음.
- 그 다음: 원재료 환산 카드 (1.13.9, 공정 = 현장 분류 — 같은 원료 · 같은 단위라 공정 칸을 더한 합계는 맞다).
- 아래 줄: [엑셀 (공정마다 시트)] — 카드마다 시트 + '품목 목록' (공정 · 구분 · 품목군 · 정한 자료 · 수불) · BOM 의 부품이 품목에 없음 n종.
- 맨 아래 품목 표: 공정 탭 (모든 공정 · 사출 · 리필 성형 · 조립 · 종이 권취 · 포장 · 분류 안 됨) · 구분 · 품목군 고르기 (원부자재는 예전처럼 ERP CODE 제품군 · 분류 · 세부). 품목 칸에 공정 · 구분 · 품목군, 묶음 품목은 "일보 품목군: Mini 600 · Pencil 400". 엑셀도 공정 · 구분 · 품목군.
- 종합 현황 위젯 `floor_stock`: 공정 하나 (모든 공정 없음) · 품목군 · 줄. 예전 '모든 공정' · '기타' 위젯은 공정 카드 묶음.
