### 2. 확정한 규칙
1. **현장 재고 위 = 피벗 표 목록**
   - 코드: `app/js/pivot.js`, `ERP.floorPivot(all)`. `p_stock.js` 의 stockTab 이 현장 재고일 때 부른다.
   - 1.11.4 의 공정별 · 대분류 칸(`floorCards`)은 없앴다.
   - 원부자재 재고의 단계 카드(RM · SM · CM)는 그대로다.
2. **표 하나** = `{ id, title, procs, divs, rows, cols, scope, zero }`
   - 저장: 설정 `floorPivots`. 모든 PC 가 같은 설정을 쓰고, 없으면 기본 표다. 설정 열림은 화면 상태다 (`ERP.state.fpiv`, 저장 안 함).
   - 공정 `procs` (비면 모든 공정) = 단계의 공정 (`INV.procOfStage`), 공정이 없으면 기타.
   - 품목군 `divs` (비면 모두) = ERP CODE 제품군 `s.line`. 이름은 `INV.lineDivName` (MINI Mini · REG Dial · PEN Pencil · CPC Click pencil · GLA Glass · MARKER Marker), 제품군이 없으면 기타.
   - 행 `rows`: 품목군 · 공정 · 단계 · 품목.
   - 열 `cols`: 없음 (현재 재고 한 칸) · 공정 · 품목군 · 단계. 행과 같은 것은 고를 수 없다.
   - 범위 `scope`: 창고+공장 · 창고 · 공장.
   - 값 = **현재 재고 수량** (`INV.rows()` — 아래 품목 표와 같은 계산). 색깔 구분 없이 더한다.
   - **기본 표** = `{ id: 'asm', procs: ['ASM'], rows: 'div', cols: 'none' }`. 제목은 "조립 재고", 머리는 "품목군 | 현재 재고".
3. **월 열 없음 (1.12.1)**
   - 1.12.0 에 저장한 열 `cols: 'month'` 는 현재 재고 한 칸으로 읽는다.
   - 연도 단추도 없다.
4. **합계**
   - 열이 공정 · 품목군 · 단계이면 줄 맨 앞에 **합계** 열을 둔다.
   - 맨 아래 **합계** 줄은 언제나 있다.
5. **단위가 섞이면 나눈다**
   - 줄 이름에 단위를 붙인다 (`Pencil · SET`, `Pencil · CT`). 합계 줄도 단위마다 따로 둔다.
   - 단위가 하나면 설명에 "단위 PCS"처럼 쓴다.
6. **재고 0 은 숨긴다**
   - 재고 0 인 줄은 숨긴다.
   - 공정 · 품목군 · 단계 열이면 모두 0 인 열도 숨긴다.
   - 설정 "재고 0인 줄도 보기"를 켜면 보인다.
7. **카드 크기**
   - 현재 재고 한 칸 표는 좁은 카드다. 여러 공정 표가 한 줄에 나란히 놓인다 (예전 칸처럼).
   - 열이 있는 표와 설정을 연 표는 넓은 카드다.
8. **칸을 누르면** 아래 품목 표를 거른다
   - 표의 공정이 하나면 그 공정, 그리고 줄 · 열의 공정 · 품목군 · 단계로 거른다.
   - 거르기는 1.11.4 와 같다: `stk_floor.proc · line · stage`, 칩 "조립 · Mini ×".
   - 품목 줄을 누르면 그 품목의 수불부가 열린다.
   - 누르면 화면이 아래 품목 표로 내려간다.
9. **[설정]** (표마다)
   - 공정 체크: 전체 + 현장에 품목이 있는 공정.
   - 품목군 체크: 전체 + 있는 품목군.
   - 행 · 열 · 범위를 고른다.
   - 제목: 비우면 자동 ("조립 · 사출 재고 (Mini)").
   - 재고 0 줄 보기.
   - 위로 · 아래로 · 표 지우기 (확인 창) · 완료.
10. **[+ 표 추가]**
    - 다음 공정의 품목군 · 현재 재고 표를 더하고 설정을 연다. 다음 공정 = 공정 하나짜리 표가 아직 없는 첫 공정 (사출, 리필 성형 …).
    - 표를 모두 지우면 [기본 표로 (조립 · 품목군)] 이 나온다.
11. **[엑셀]**: 보이는 표 그대로 저장한다 (머리 · 줄 · 단위별 합계, `floor_pivot_<날짜>.xlsx`).
12. **좁은 화면**: 표는 `.tbl-wrap` 안에서 옆으로 밀린다.
13. **글자**: 한국어 / 베트남어 둘 다. 단계는 'Giai đoạn' 으로 써서 공정 'Công đoạn' 과 구분한다.
14. **종합 현황 위젯 (1.12.2)** `floor_stock` — "현장 재고 (공정별 현재 재고)", 위젯 추가의 재고 칸에 있다.
    - 현장 재고 위 표와 같은 계산 · 모양이다 (`ERP.pivot.build` · `tableEl`, `fromWidget`).
    - 가로 1칸이 기본이고, 여러 개를 넣을 수 있다.
    - ⚙ 에서 공정(모든 공정 · 각 공정 · 기타, 기본 조립) · 행 · 열을 고른다. 위젯 설정은 `meta.dash` 의 그 위젯 `o: { proc, rows, cols }`.
    - 칸을 누르면 현장 재고로 가서 그 공정 · 품목군 품목을 보인다 (`ERP.pivot.pick`).
    - **기본 배치에는 넣지 않는다** — 사용자 위젯 배치는 바꾸지 않는 규칙이라, "+ 위젯 추가" 에서 사용자가 넣는다.
15. **이번 달 포장 누계 = pcs (1.12.3)** — 종합 현황 위젯 `kpi_pck_month`.
    - 값 = 포장 일보의 pcs 칸(`ok_ea`) 합이다 (`ctx.pckPcs(from, to)`). 전월 동기 대비도 pcs 로 계산한다.
    - **pcs 가 비었거나 0 인 줄은 세트를 pcs 로 세지 않는다**. 카드에 "pcs 없는 일보 N줄 (M세트) 빠짐" 으로 알린다.
      - 이 PC 의 포장 일보 1,904줄 중 124줄이 세트만 있고 pcs 가 0 이다 (2026-10 은 8줄 · 16,664세트).
      - 그 줄의 PO 번호(4700026501-1, 5100358562/1 …)는 수주 표와 맞지 않아 pcs ÷ 세트로 바꿀 근거가 없다. pcs 가 있는 줄은 수주의 pcs ÷ 세트와 1,762 / 1,774 가 같다.
    - 기준일 포장 실적(`kpi_pck_day`)은 세트 그대로다 (요청은 이번 달 누계만).
    - 휴대폰 요약 `kpi.pckMonth` 에 `ea` · `prevEa` · `noN` · `noSets` 를 더했다. 구글 웹 앱(`google/Code.gs`)은 `ea` 가 있으면 pcs 로 보이고, 옛 요약은 세트로 보인다 (15차 규칙: 휴대폰 요약 = 종합 현황과 같은 숫자).
16. **숫자 카드 아래 지난달 값 (1.12.4)** — 새 칸(위젯)이 아니라 **같은 카드 안의 남는 아래쪽**에 둔다 (`withLast`, `.kpi-prev` = 카드 맨 아래 `margin-top:auto`, 점선 위).
    - **이번 달 포장 누계** → "지난달 (9월) 누계": 지난달 1일 ~ 말일 포장 pcs. pcs 없는 줄이 있으면 "(pcs 없는 N줄 빠짐)". 위의 ▲▼% 는 그대로 전월 동기 대비다.
    - **이번 달 신규 수주** → "지난달 (9월)": 수주일이 지난달인 수주 pcs · 건수.
    - **이번 달 수주량 (Checking)** → "지난달 (9월)": Checking 일이 지난달인 수주 pcs (전월 대비 % 의 그 값, 품목군 거르기도 같음).
    - 휴대폰 요약 `pckMonth.lastEa` · `lastM`, Code.gs 는 포장 누계 줄 뒤에 "지난달(9월) N pcs". (휴대폰에는 신규 수주 · 수주량 카드가 없다.)
17. **기본 배치 = 사용자 배치 (1.12.5)** — 종합 현황 `DEFAULT`.
    - 순서: 이번 달 포장 누계 · 이번 달 신규 수주 · 이번 달 수주량 (Checking) · 조립 재고 (`floor_stock` 조립) — 한 줄, 그 아래 월별 수주량 (차트, 4칸) · 공정별 실적 (4칸) · 월별 조립 생산량 (조립 · 차트, 4칸).
    - 안전재고 미달은 뺐다. 예전 기본의 나머지 (기준일 포장 · 납기 · 일별 조립 · 목록 · 흐름 · 자료 최신 · 일보 입력 현황) 도 사용자 배치에 없어 넣지 않았다 — "+ 위젯 추가" 에서 넣는다.
    - 1.12.4 의 지난달 값은 그대로다.
    - 이 PC 의 저장된 배치(사용자가 직접 꾸민 것)는 같은 위젯 · 설정 그대로 이 순서로만 저장했다 (전에는 큰 위젯이 중간에 있어 빈칸 채우기로 같은 화면이었지만, 좁은 화면에서는 순서가 달랐다).
    - 기본 배치를 바꾸지 않는다는 규칙(CLAUDE.md "사용자 설정 · 위젯 배치")은 사용자가 이 배치를 기본으로 정해 달라고 해서 바꾼 것이다.
