## PROMPT

너는 BOSUNG VINA(베트남 색연필 공장) ERP를 유지보수하는 시니어 개발자다. 기능과 숫자 정의는 그대로 두고, 아래를 **11차(v1.6.0) 위에서** 한다. 이름 · 글자를 짐작해서 쓰지 말고, 모르면 사용자에게 묻는다.

### 1. 사용자 요청 (2026-10-20, 요지)
> 품목·재고를 나눠 달라고 했는데 아직 그대로다. 현장 재고와 원부자재는 따로 간다 — 아예 메뉴를 **품목 // 현장 재고 // 원부자재 재고** 로 나눠라. 품목·재고 안에 다 넣지 말고.
> ECOUNT 비교는 왜 있나? 다음 달부터 ECOUNT 는 없애고 쓰지 않는다. 그래서 이 ERP 를 만드는 것이다.
> 분류 끝의 (?) 물음표는 왜 있나? 모르면 물어보고, 혼자 글씨를 쓰지 마라.

확인한 답: 확인되지 않은 이름은 **코드만 표시** (이름은 사용자가 정하거나 ERP CODE 설명 파일로 채운다).

### 2. 확정한 것
1. 왼쪽 메뉴: 종합 현황 · 수주 관리 · 생산 관리 · **품목** · **현장 재고** · **원부자재 재고** · 제품 · BOM · 배합 · (데이터) 엑셀 · 구글 연동 · 설정. 예전 "품목 · 재고" 메뉴는 없다.
   - 품목 (`#/items`): 품목 마스터 · 코드 사전 · 자료 점검 · 예시 자료
   - 현장 재고 (`#/floor`): 현장 재고 · 생산 반영 · 수불 입력 · 수불 내역
   - 원부자재 재고 (`#/materials`): 원부자재 재고 · 수불 입력 · 수불 내역 · 발주 · 안전재고 · 외주 입출고
2. 수불 입력 · 수불 내역은 메뉴마다 그 메뉴의 품목만 다룬다 (`INV.groupOf`: RM · SM · CM = 원부자재, 그 밖 = 현장). 다른 쪽 품목을 넣으면 "원부자재 재고 메뉴에서 입력" / "현장 재고 메뉴에서 입력" 으로 막는다. 현장 재고 수불 입력의 기본은 조정 · 공장. 생산 반영 자동 행은 현장 재고 수불 내역에만 나온다. 발주 · 안전재고는 원부자재만.
3. ECOUNT 비교는 없앤다: 비교 탭, 비교용 표 `ecount_snap`, ECOUNT 재고현황의 "비교만" 방식. ECOUNT 재고현황은 "기초재고로 설정" 하나 (다시 올리면 그 범위의 기초재고를 바꾼다 — 확인 창).
4. 짐작한 이름을 쓰지 않는다: 내장 코드 사전에서 확인되지 않은 코드(`guessed`)의 이름을 비웠다. 화면에는 코드만 보인다 (묶음 단계는 WIP06·x6 · WIP15·25·35 · WIP21·31…). 물음표(?) 표시도 없앴다. 화면 글에도 짐작한 이름을 쓰지 않는다 (CM 은 "CM").
   - 이름 미정 단계: CM · WIP06·x6 · WIP15·25·35 · WIP11 · WIP21·31… · WIP55
   - 이름 미정 제품군: GRA · MIX / 세부: NEON · PAS · CLA · CRA · HF · RB · BRR · BARREL · NCONE · SP · HD · ASSY · SYS · PBAG
   - 이름 미정 분류: RM-OIL · SM-PAPER · SM-SRT · SM-LB · SM-BLISTER · SM-PAD · SM-CDU · SM-MANILA · CM-LB · CM-PET · CM-HOTFOIL · CM-INMAY · CM-GLUE · CM-TAPE · CM-FILM · CM-POF · CM-FOIL · CM-TP
5. 물음표 표시를 쓰지 않는다: 단계 카드 · 재고 표의 "이동?" 은 "이동 누락" (말풍선 "이동 누락 의심").
6. 화면에 "null" 글자가 보이지 않게 한다 (빈 표 · 빈 목록에서 보이던 것을 고침).
7. 코드 사전(품목 → 코드 사전): 이름 미정 줄은 이름 칸이 비어 있고 코드 옆에 "이름 미정". 이름을 넣으면 바로 화면 전체에 이름이 나오고, 이름을 모두 지우면 다시 코드만. ERP CODE 설명 파일을 올리면 그 파일의 코드는 확인된 이름이 된다.

### 3. 코드 규칙
- `app/js/p_stock.js`: `ERP.pages.items` · `ERP.pages.floor` · `ERP.pages.materials` (같은 `stockPage` 틀). 탭 → 메뉴 표 `TAB_PAGE` (master · codes · check · legacy → items, floor · post · fentry · fledger → floor, mat · entry · ledger · reorder · outsource → materials). 메뉴마다 고른 탭: `ERP.state.itemTab` · `floorTab` · `mtab`.
- 다른 화면에서 재고 탭으로 갈 때는 **`ERP.goStock(탭)`**. `ERP.openStock(단계)` 는 단계 그룹의 메뉴를 그 단계 필터로 연다.
- 예전 방식 `ERP.state.matTab = '탭'; ERP.goto('materials')` 도 맞는 메뉴로 보낸다 (`takeRequest` — 다른 메뉴면 주소를 바꾸고 바로 그 메뉴를 그린다). 예전 탭 이름 `'stock'` → 단계 그룹의 재고 탭, `'compare'` → 원부자재 재고.
- 상태 키: 수불 입력 `txe` (원부자재) / `txe_floor` (현장), 수불 내역 `txl` / `txl_floor`, 재고 표 `stk_mat` / `stk_floor`.
- `app/js/main.js` NAV 3줄, 배지: 현장 재고 / 원부자재 재고 각각 (안전재고 미달 + 마이너스, 그 그룹 품목만).
- `app/js/inv.js`: 내장 사전의 guessed 이름은 빈칸. `INV.label` 은 guessed 면 코드, `INV.labelShort` 도 같음. 새 코드를 내장 사전에 넣을 때 이름을 모르면 `guessed: true` 와 빈 이름으로 둔다.
- 코드 사전 저장(`codesTab` 의 `save`): guessed 줄은 빈 이름에서 시작 (짐작한 다른 언어 이름이 딸려 저장되지 않게), 이름을 넣으면 `guessed: false`, 이름이 모두 비면 `guessed: true`. 저장 뒤 화면을 다시 그리지 않는다 (입력 포커스 유지 — 그 줄의 표시만 바꿈).
- DOM 에 붙일 때 빈 값이 섞일 수 있으면 `ERP.put(el, ...)` (core.js) — `Element.append(null)` 은 "null" 글자를 붙인다. `ERP.grid` 의 빈 표도 이것으로 고쳤다.
- 자료 올리기 결과 버튼: 현장 실사 · 생산일보 → 현장 재고, 재고현황 · 수불 → 원부자재 재고, 품목 · 창고 · 코드 → 품목.
- 종합 현황 위젯 · AI 비서 버튼도 `ERP.goStock` 을 쓴다 (마이너스 재고 위젯은 원부자재에 마이너스가 없고 현장에만 있으면 현장 재고로). AI 비서의 재고 답변 버튼은 첫 품목이 속한 메뉴 ("현장 재고 열기" / "원부자재 재고 열기").

### 4. 지켜야 할 것
- 모르는 이름 · 글자는 짐작해서 쓰지 않는다. 코드만 보이고, 사용자에게 묻는다.
- ECOUNT 비교 기능을 다시 만들지 않는다 (ECOUNT 는 2026-11 부터 쓰지 않음). ECOUNT 파일은 처음 자료(품목 · 창고 · 코드 · 기초재고)를 옮길 때만 쓴다.
- 현장 재고와 원부자재 재고는 메뉴 · 수불 입력 · 수불 내역 · 배지까지 따로 간다. 생산 반영은 원부자재를 차감하지 않는다 (11차 규칙 그대로).
- 공개 저장소다: 공장의 실제 엑셀은 저장소에 넣지 않는다.
