## PROMPT

너는 BOSUNG VINA(베트남 색연필 공장) ERP를 유지보수하는 시니어 개발자다. 기능과 숫자 정의는 그대로 두고, 아래를 **13차(v1.8.0) 위에서** 한다. 이름 · 글자를 짐작해서 쓰지 말고, 모르면 사용자에게 묻는다.

### 1. 사용자 요청 (원문, 2026-10-21 · 첨부 `창고입출고및 안전재고.xlsx`, ECOUNT 재고현황 `393jdK3i3gGcfy9f.xlsx`)
> Nhập trong kỳ 입고 / Xuất trong kỳ 출고 / Tồn cuối kỳ 재고 — 원부자재 재고에 반영해줘.
> 엑셀 G9 칸은 세관신고 코드이다. H9는 품목명인데 베트남어로되있으면 한글로 번역해서 넣고 I9는 입출고 및 색깔을 표시하는 칸인데 이건 너가 분리해서 적절하게 나눠서 만들어줘. D9는 업체코드 E9는 입출고 하거나 받은곳 명칭이다. F9는 G9의 소분류 코드이다. A9는 무시하고 C9의 날짜만 반영해줘.
> (두 번째 파일) 마이너스 되있는건 0으로 바꾸고 창고입출고 파일이 기초재고이고 이파일로 보완한다. 코드들을 대조해서 매칭시키고 중복된수량은 창고입출고 수량으로 대체한다.

물어서 정한 것:
- 재고 계산 = **1~10월 입출고까지 반영** — 1월 1일(첫 입출고일 전날) 기초재고 = 기말 재고 − 입고 + 출고, 그 뒤 입출고를 더해 마지막 날 재고가 파일의 재고(Tồn cuối kỳ)와 같게. 계산이 마이너스인 품목은 기초재고 0 + 마지막 날 조정.
- 품목 구분 = **출고 내용으로** — 원료(NL)로 출고 → 원재료 RM (kg), 자재(vật tư)로 출고 → 부자재 SM (개). 소모품은 나중에 품목 화면에서.

### 2. 자료 (이 PC, 2026-10-21)
- 창고 입출고장: 시트 `Nhập - xuất`, 7 · 8행 머리글, 9행 열 번호(01 02 03 04 05 06 17 07 …), 10 ~ 5,619행 입출고 5,610줄 (2026-01-02 ~ 10-16), 그 아래 3,600여 줄은 0 만 있는 빈 양식. 안전재고 시트는 없다.
- J = 개당 kg, L/M 입고 kg/개, N/O 출고 kg/개, P/Q 기말 재고 kg/개 — 기말 재고는 줄마다 누적이 아니라 품목마다 같은 값이 반복 (422 / 426 품목).
- 품목코드(F) 426개 (대소문자만 다른 것을 합치면 418), 세관 코드(G) 62종, 업체 39곳 (부서 · 거래처).
- ECOUNT 재고현황: `품목코드 · ERP CODE · Mã XNK · 품목명[규격] · 단위 · 재고수량 · Số Set · Số PCS` 309행 (원재료 102 · 부자재 109 · 소모품 41 · 반제품 50 · 완제품 6 · 마니라 1), 마이너스 4행 (모두 완제품).

### 3. 확정한 규칙
1. 창고 품목 맞추기 (반영할 때):
   - 같은 코드의 원부자재가 있으면 그 품목.
   - 창고가 카톤 · 케이스에 **제품번호(마지막 마디 0xx)** 를 쓴 경우 → 세관 코드(Mã XNK)가 같고 앞 3마디가 같은 원부자재가 하나면 그 품목 (예: 04-5225-0-005 → 카톤 04-5225-0-806).
   - 한 ERP 품목에 창고 코드가 둘 이상 붙으면 **합치지 않는다** — 같은 코드가 그대로 있는 것만 붙이고 나머지는 자기 코드로 (같은 물건일 수 있는 쌍은 미리보기 · 결과에 알린다).
   - 같은 코드가 완제품 · 반제품(FG · SG · WIP)이면 원부자재로 넣지 않는다 (현장 재고 품목, 줄도 넣지 않음).
   - 그 밖은 새 원부자재 품목: 코드 F, 이름 H (베트남어면 한국어 — `EC.viToKo`, 원래 이름은 `name_vn`), 세관 코드 G (`xnk`), 개당 kg J (`kg_per_ea`), 구분 · 단위는 출고 내용으로.
2. 기초재고: 창고 범위(WH), 첫 입출고일 전날, 품목마다 기말 − 입고 + 출고 (그 품목 단위: kg 이면 kg 칸, 그 밖은 개 칸, 비면 개당 kg 로 환산). 기초재고가 0 인 품목도 줄을 만든다 (ECOUNT 보완이 같은 품목을 다시 넣지 않게). `grp: 'wh'`. 다시 올리면 이 줄들만 바꾼다.
3. 입출고: 입고 = 외부 → 창고, **출고 = 창고 → 외부 (원부자재 재고에서 빠짐)** — 11차부터 생산 반영이 원부자재를 차감하지 않으므로 창고에서 나간 것은 출고로 본다 (부서로 나간 생산 투입 포함). `src: 'wh'`, 같은 기간을 다시 올리면 바꾼다. 업체코드 `partner_code`, 업체 `partner`.
4. I 칸 (`EC.splitContent`): 용도 `purpose` (생산 투입 · 생산용 입고 · 외주 가공 출고/입고 · 한국 발송 · 재입고 · 반품), Lot `lot` (Lot 뒤 · 문구 뒤 번호), 색깔 `color` (WHITE · LOGO RED · PANDA ORANGE · SKY BLUE …), 비고 `note` (팔레트 수 · 생산일 · 정해진 문구가 아닌 원문).
5. ECOUNT 재고현황: ERP CODE · Mã XNK 칸이 있으면 품목도 만든다 (있는 칸만, '숨김 후보' 없음). 창고 입출고장과 같이 올리거나 창고 기초재고(`grp: 'wh'`)가 이미 있으면 방식 = **보완** — 이미 기초재고가 있는 품목은 그대로 (창고 수량), 없는 품목만 더하고 마이너스는 0, 공정 중(WIP) 품목은 현장 실사 기준이라 넣지 않는다. `grp: 'fill'`.
6. 업로드 화면: 같이 올린 파일끼리 `job.onBatch(jobs, self)` (XL.analyze 가 작업을 복사하므로 self 를 고친다).

### 4. 코드
- `ecount.js`: `wh_ledger` 인식기 · `resolveWh` · `applyWhItems` · `applyWhOpen` · `applyWhTx` · `EC.viToKo` · `EC.splitContent`, ECOUNT 재고현황의 품목 작업 · `fill` 방식.
- `schema.js`: 품목 `name_vn` · `kg_per_ea`, `xnk` 이름 "세관신고 코드 (Mã XNK)", 수불 `partner_code` · `purpose` · `lot` · `color`.
- `p_stock.js`: 수불 내역 (거래처 (업체코드) · 용도 · Lot · 색깔, 엑셀 칸), 품목 상세 (세관신고 코드 · 베트남어 원문 · 개당 kg · 기초재고 출처).
- `p_data.js`: 안내 · 같이 올린 파일 처리 · 창고 기초재고 재설정 확인.

### 5. 지켜야 할 것
- 창고 입출고장이 원부자재의 기준. ECOUNT 는 없는 품목만 보완 (ECOUNT 는 2026-11 부터 쓰지 않음).
- 서로 다른 코드를 짐작으로 한 품목에 합치지 않는다 — 같은 물건일 수 있으면 사용자에게 묻는다.
- 공개 저장소: 공장의 실제 엑셀은 저장소에 넣지 않는다 (시험은 코드로 만든 가짜 엑셀).
