## PROMPT

너는 BOSUNG VINA(베트남 색연필 공장) ERP를 유지보수하는 시니어 개발자다. 사용자는 대부분을 네가 판단해 적용하길 원하고, 정말 필요한 것만 묻는다. 마스터 데이터는 사용자가 화면·엑셀에서 수정한다. 기존 기능(수주·생산일보·BOM/MRP·나만의 AI 비서·구글 연동·설치 파일)은 그대로 유지하고, 아래 변경을 **최신 소스(5차) 위에** 반영한다.

### 1. 목표와 확정된 결정 (2026-10-16 사용자 답변)
1. **기존 백데이터(샘플)는 예시로만** 쓴다. 품목·창고·재고는 ECOUNT에서 내려받은 자료로 다시 구성한다.
2. **재고의 기준은 이 ERP**다. ECOUNT 자료는 품목·창고 마스터와 **기초재고(2026-10-16)** 로 가져온다. 그 뒤의 입고·출고·이동·생산은 이 ERP에서 관리한다.
3. **재고 범위는 2묶음**이다: `창고`(ECOUNT "Kho thành phẩm 외")와 `공장`(ECOUNT "SẢN XUẤT 외"). 화면은 창고 / 공장 / 합계 3열로 보여 준다.
4. **수불 입력은 엑셀 업로드 + 화면 입력** 두 가지를 모두 지원한다.
5. **생산일보를 올리면 재고에 자동 반영**한다: 생산량은 입고, BOM이 있으면 부품·원료를 차감한다. BOM이 없는 품목은 경고한다. 설정에서 끄거나 "입고만"으로 바꿀 수 있다.
6. 기존 샘플(수주·생산일보·BOM·배합표·입출고장·마스터 등)은 **행마다 "예시" 표시를 붙여 남기고**, 설정에서 예시 행만 한 번에 지울 수 있게 한다. 새로 올리거나 직접 입력·수정한 행은 예시가 아니므로 지워지지 않는다.
7. **실무자가 보기 편하게**: 모든 품목을 ERP CODE로 자동 분류해 공정 흐름 순서로 보여 준다(원재료 → 부품 → 스탬핑 → 조립 → 포장).
8. **자료 올리기 편하게**: 엑셀 여러 개를 한 번에 끌어다 놓으면 종류를 자동 인식한다. 미리보기를 보여 준 뒤 한 번에 반영하고, 되돌릴 수 있게 한다.

### 2. 입력 자료 (2026-10-16 내려받은 파일 기준)
파일명은 업로드 중 한글이 깨지므로(`____.xlsx`) **파일명이 아니라 내용으로** 인식한다. 공통 형식은 다음과 같다:
- 1행 `회사명 : BOSUNG VINA CO.,LTD …`
- 2행 머리글
- 마지막 행 내보낸 시각 (`16/10/2026  오후 12:19:50`)

| 자료 | 인식 기준 (2행 머리글) | 내용 | 행 수 |
|---|---|---|---|
| 품목등록 | `품목코드 · Mã XNK · 품목명 · ERP CODE · 품목구분 · Đơn vị chính · 안전재고수량 · 안전재고관리-창고이동 · BOM등록` | 통합 품목 마스터. 품목구분 [원재료] 120 · [부재료] 464 · [반제품] 1,456 · [제품] 224 · [상품] 1. 안전재고는 52품목(전부 원재료)에 있고, BOM등록 열은 전부 비어 있음 | 2,265 |
| 창고리스트 | `창고코드 · 창고명 · 구분 · 생산공정명 · 외주거래처명 · 사용 · 추가사업장명` | 창고 4: 00004 완제품, NVL 원부자재, NVLN 사출원료, WIP<br>공장 3: 00003 포장, BS05 권취, WIP00 생산<br>외주 4: EP1·EP2 사출, GC01 권취, HF01 포장 | 11 |
| 재고현황 (창고) | `품목코드 · ERP CODE · Mã XNK · 품목명[규격] · 단위 · 재고수량 · Số Set · Số PCS`<br>1행: `… / Kho thành phẩm 외 / 16/10/2026 / Số dư Tồn Kho` | 창고 쪽 재고 (원재료·부자재·소모품 위주). 끝에 `합계` 행 | 314 |
| 재고현황 (공장) | 같은 머리글<br>1행: `… / SẢN XUẤT 외 / 16/10/2026 / …` | 공장 쪽 재고 (반제품 위주). 마이너스 158품목 | 962 |
| ERP CODE 설명 | 1행 `ERP CODE 설명`, 3행 `설명 · Mô tả · ERP CODE` 가 3묶음 | 코드 체계 사전 (한/베 이름) | 34개 코드 |

- 재고현황 1행의 읽는 법:
  - `Kho thành phẩm 외` / `SẢN XUẤT 외` → 범위(`창고` / `공장`)
  - `16/10/2026` → 기준일 (dd/mm/yyyy)
- `Số Set` · `Số PCS` 는 ECOUNT가 계산한 환산값이다(CT·SET 단위 품목만 있음). 그대로 저장하고, 여기서 역산한 환산 비율(CT당 set, set당 pcs)을 품목의 보조값으로 둔다.
- 기존 샘플과 품목코드가 일치하는 정도:

  | 샘플 자료 | 일치 / 전체 |
  |---|---|
  | 수주 품번 | 71 / 83 |
  | 조립 일보 코드 | 294 / 305 |
  | 스탬핑 일보 코드 | 13 / 13 |
  | 권취 일보 코드 | 8 / 8 |
  | 포장 일보 코드 | 64 / 70 |
  | 반제품 목록 | 1,299 / 1,301 |

  사출 일보는 부품 종류(Barrel 등)로 적혀 있어 품목코드와 연결되지 않는다.

형식은 `단계-제품군(또는 분류)-세부-품목코드` 이다.

| `WIP-MINI-SUP-…` | 조립 완료 · 미니 · 스매쉬업 |

### 4. 데이터 구조 (`app/js/schema.js`)

**`items` — 통합 품목 마스터** (키 `code` = 품목코드). 기존 `items` 표를 확장한다.

| 열 | 내용 |
|---|---|
| `code` | 품목코드 |
| `name` | 품명 |
| `erp_code` | ERP CODE |
| `xnk` | Mã XNK |
| `etype` | 품목구분 |
| `unit` | 원본 단위 |
| `safety` · `safety_move` | 안전재고 · 안전재고관리-창고이동 |
| `stage` · `line` · `sub` · `cat` | ERP CODE에서 자동 분리 |
| `set_per_ct` · `pcs_per_set` | 환산 비율 (보조값) |
| `hidden` | 숨김 |
| `src` | `ecount` / `local` |
| `note` | 비고 |

- 단위 표기는 화면에서만 통일한다(pcs→PCS, KG·KGS→kg). 원본 값은 보존한다.
- 품목등록을 다시 올리면 신규는 추가, 변경은 갱신한다. 파일에 없는 품목은 지우지 않고 `숨김 후보`로만 표시한다.
- 사용자가 만든 품목(`src=local`, 사용자 정의 BOM용)은 ECOUNT 업로드로 바뀌지 않는다.
- 기존 `materials` · `products` · `semi_items` · `sub_materials` · `semi_stock` 은 예시 자료로 남긴다. 화면과 계산은 `items` 를 기준으로 한다. 단, BOM 차감에 쓰는 구성 정보(products의 배럴·노즈콘·리필 코드, recipes 배합)는 계속 참조한다.

**나머지 표**

| 표 | 키 | 열 / 동작 |
|---|---|---|
| `warehouses` 창고 | `code` | `code, name, kind(창고/공장/외주), process, partner, active, site, scope(창고/공장)`. 외주 4곳은 `공장` 범위로 묶고 외주처 이름을 남긴다. |
| `code_dict` 코드 사전 | `level+code` | `level(stage/line/sub/cat), code, ko, vi, order, guessed` |
| `stock_open` 기초재고 | `scope+code` | `date, scope(창고/공장), code, qty, sets, pcs, unit, file`<br>ECOUNT 재고현황 첫 업로드 = 기초재고(기준일 2026-10-16). 다시 올리면 **"기초재고 재설정"(확인 필수)** 또는 **"비교만"** 중 선택. |
| `stock_tx` 재고 수불 | — | `date, doc_no, kind, from_scope, to_scope, code, qty(품목 주 단위), partner, ref, src, note`<br>`kind`: `IN` 입고 · `OUT` 출고 · `MOVE` 이동(창고↔공장) · `PROD` 생산입고 · `USE` 생산소모 · `ADJ` 조정<br>`ref`: 수주번호 / 일보 id<br>`src`: `manual` / 파일명 / `daily:<공정>:<일자>` |
| `ecount_snap` 비교용 ECOUNT 재고 | `date+scope+code` | 기초재고 이후 올린 ECOUNT 재고현황을 보관하고, 이 ERP 재고와 차이를 보여 준다. |
| `uploads` 업로드 이력 | — | `at, kind, file, scope, date, rows, added, changed, removed, mode`<br>직전 상태로 되돌리기를 지원한다. |

- 기존 원부자재 `inout`(샘플)은 기준일 이전 자료라 재고 계산에 쓰지 않는다. "예시 입출고장"으로만 보여 준다.

### 5. 계산 규칙 (`app/js/calc.js`)
- **현재고(범위별) = 기초재고 + 기준일 이후 수불(조회일까지)**. 범위별로 이렇게 더한다:
  - `IN` → `to_scope` +
  - `OUT` → `from_scope` −
  - `MOVE` → `from_scope` −, `to_scope` +
  - `PROD` → 공장 +
  - `USE` → 공장 −
  - `ADJ` → ±
- 화면마다 **기준일과 마지막 수불일**을 표시한다.
- **수불부(품목별 원장)**: 기초 → 일자별 입고 / 출고 / 이동 / 생산 / 소모 / 조정 → 잔액.
- 상태: `마이너스(<0)` / `미달(< 안전재고)` / `임박(<120%)` / `정상` / `기준없음` / `0`.
- **이동 누락 의심**: 한 범위는 +, 다른 범위는 − 인 품목. 합계는 정상일 수 있다.
  - 예: R-001 BEE WAX — 창고 +1,695 / 공장 −790.53 → 합계 904.47
  - 기초재고 기준 71품목이 해당한다(숨긴 테스트 품목 4개를 더하면 75). [이동 전표 만들기] 버튼으로 바로 정리할 수 있게 한다.
- 완제품(FG, 단위 CT)은 `CT · set · pcs` 를 함께 보여 준다. 수주 상세에 해당 품번의 FG 재고(set)를 표시한다.

**생산일보 → 재고 자동 반영** (설정 `prodPost` = `off` / `in` / `in_bom`, 기본 `in_bom`)
1. 기준일 다음 날부터의 일보만 반영한다. 자동 수불(`PROD`·`USE`)은 `stock_tx` 에 저장하지 않고 **일보에서 매번 다시 계산**한다. 그래서 같은 일보를 다시 올려도 중복되지 않는다.
2. 생산입고 `PROD`: 일보 코드 = 품목코드일 때 양품 수량만큼 공장 +.
   - 포장(PCK)은 set → CT 환산(`set_per_ct`)이 필요하다. 환산 정보가 없으면 반영하지 않고 목록으로 보여 준다.
3. BOM 소모 `USE`: 1단계 하위 구성품 × 생산량을 공장 −. 구성 정보는 아래 순서로 찾는다:
   1. 사용자 정의 BOM `bom_lines`
   2. 조립(ASM)은 `products` 의 배럴·노즈콘·리필·홀더·스푼 코드
   3. 리필(REF)은 `recipes` 배합 (g/개 → kg)
   4. 포장(PCK)은 `bom`/`item_bom` 의 색상 구성·마니라
4. 미리보기를 보여 준 뒤 반영한다. 미리보기에 나오는 것:
   - 생산입고 n건, 소모 n건
   - **BOM 없음** n품목
   - **품목코드 아님** n건 (사출 일보처럼 부품 종류만 적힌 줄)
   - 환산 없음 n건
5. 현재 BOM·배합표는 예시 데이터라는 경고를 같이 표시한다.

**그 밖의 계산**
- MRP: 반제품·원재료 재고는 이 현재고를 쓴다. 배합표 원료명은 `items`(RM) 이름으로 연결하고, 연결 안 된 원료는 목록으로 보여 준다.
- AI 비서 도구(`material_stock`, `overview`, `briefing`, `reorder`, `mrp` 등)는 새 현재고를 읽고, 답할 때 **기준일과 마지막 수불일**을 함께 말한다. 내장 모드 질문 예시도 새 코드(품목코드·ERP CODE)로 갱신한다.

### 6. 화면
1. **품목·재고** (새 메뉴, 원부자재 재고 화면을 대체)
   - 위: 공정 흐름 카드 15칸(원재료 → … → 박스 포장). 칸마다 품목 수, 마이너스 수, 안전재고 미달 수를 보여 준다. 칸을 누르면 아래 표가 그 단계로 필터된다.
   - 필터:
     - 단계 · 제품군 · 세부/고객 · 분류 · 범위(창고/공장/전체)
     - 상태: 마이너스, 미달, 이동 누락 의심, 재고 0 숨김
     - 검색: 품목코드·ERP CODE·Mã XNK·품명 (띄어쓰기·대소문자 무시)
   - 표 열: 품목코드 · 품명 · ERP CODE(칸별 색 칩) · 단위 · 창고 · 공장 · 합계 · set · pcs · 안전재고 · 상태 · 최근 7일 수불. 열 정렬, 현재 보기 그대로 엑셀 내보내기.
   - 품목 상세(옆 패널): 기본 정보, 범위별 재고, **수불부**, 쓰이는 BOM, 관련 수주·생산일보, [입고/출고/이동 입력] 버튼.
2. **수불 입력** (같은 메뉴의 탭)
   - 엑셀처럼 여러 줄 입력: 일자 · 구분 · 범위(From→To) · 품목코드(코드·ERP CODE·품명 자동완성) · 수량(주 단위 표시) · 거래처 · 비고.
   - 엑셀에서 복사해 붙여넣기, Enter로 다음 칸 이동, 최근 입력 불러오기.
   - 저장 전 검사: 없는 품목코드, 단위, 마이너스가 될 출고는 경고.
   - 입력한 수불 목록: 조회, 수정, 삭제, 전표번호 묶음.
3. **종합 현황** 추가: 단계별 재고 요약, 마이너스·이동 누락 의심 수, 안전재고 미달, **자료 최신 여부**(품목·기초재고·수불·생산일보·수주의 마지막 업로드일; 1일 이상 지나면 노란 표시).
4. **자료 점검** 탭: 품목등록에서 찾은 문제를 목록과 엑셀로 내보내 ECOUNT/엑셀에서 고칠 수 있게 한다. 2026-10-16 자료 기준:
   - ERP CODE에 공백 2 (`RM-SCOIL-F2BAY -…`), 빈 칸 18 (`SM---52-7250B` 등), 품목코드로 끝나지 않음 13, 중복 2 (`FG-PEN-CRA-68-7409-L-002`, `SG-PEN-30CT-6874090215`)
   - 품목구분과 ERP CODE 단계 불일치 124 (예: `SM-…` 인데 [반제품] 41, `WIP00-…` 인데 [부재료] 36)
   - 단위 없음 1 (테스트 품목 11개 제외), 단위 표기 혼재 13 (pcs/KGS/KG), 접두어 `FD-` 1 (FG 오타로 보임 → FG로 분류)
   - 생산 반영 후: BOM 없는 생산 품목, 품목코드가 아닌 일보 코드
5. **코드 사전**:
   - 단계·제품군·분류 이름(한/베) 편집, 순서 변경, "확인 필요" 표시 해제.
   - **ERP CODE 만들기 도우미**: 단계-제품군-세부를 드롭다운으로 고르면 규칙에 맞는 코드 문자열을 만들어 복사한다 (신규 품목 등록용).
6. **설정**:
   - 생산 자동 반영(끄기 / 입고만 / 입고+BOM 소모)
   - 기초재고 기준일 보기·재설정
   - **예시 데이터 한 번에 삭제**: 표마다 예시 행 수를 보여 주고, 고른 표의 예시 행만 지운다. BOM 차감에 쓰는 예시 BOM·배합표는 실제 BOM이 없으면 기본으로 남긴다.

### 7. 자료 올리기 (엑셀·구글 연동 → 첫 카드 "자료 올리기")
1. 여러 파일을 한 번에 끌어다 놓는다. 파일마다 종류·범위·기준일·행 수를 자동 인식한다:
   - 2장 표의 머리글 기준으로 판단하고, 시트명·파일명은 보지 않는다.
   - 머리글 행은 처음 10행에서 찾는다.
   - `합계` 행과 시각 행은 제외한다.
   - 인식 대상: ECOUNT 5종, 수불 양식, KHO NVL 입출고장, 생산일보·수주 등 기존 양식.
2. 미리보기:
   - 품목: `신규 n · 변경 n · 이번 파일에 없음 n`
   - 기초재고: `기준일 · 범위 · 품목 수 · 마이너스 수 · 합계`. 합계는 원본 `합계` 행과 대조해 일치 여부를 표시한다.
   - 수불: `입고/출고/이동 n건, 없는 품목코드 n`
   - 생산일보: 5장의 반영 미리보기
3. **[모두 반영]** 으로 한 번에 반영하고 업로드 이력에 남긴다. **[되돌리기]** 를 지원한다.
4. **수불 엑셀 양식**(받기 버튼 제공): `일자 · 구분(입고/출고/이동/조정) · 출발 범위 · 도착 범위 · 품목코드 · 수량 · 거래처 · 비고`.
   - KHO NVL 입출고장도 그대로 올릴 수 있다:
     - 입고 → 창고 입고
     - 출고 → 창고→공장 이동 (반영 전에 바꿀 수 있음)
   - 품목코드가 없고 Mã XNK만 있는 줄은 후보 품목을 보여 주고 고르게 한다.
5. 업로드 안내 상자에 다음을 보여 준다:
   - 어떤 자료를 어떤 화면에서 내려받는지
   - 권장 주기: 수불·생산일보는 매일, 품목은 바뀔 때, ECOUNT 재고는 비교가 필요할 때
   - 자료별 마지막 업로드일

## 11. 6차 구현 결과 (2026-10-16, v1.1.0)

### 실무자 사용 순서
| 언제 | 할 일 | 화면 |
|---|---|---|
| 매일 | 생산일보(공정별)를 올린다 → 생산량 입고 + BOM 자재 차감이 재고에 자동 반영 | 엑셀·구글 연동 → 엑셀 업로드 |
| 매일 | 입고·출고·이동·조정: 수불 양식 또는 KHO NVL 입출고장을 올리거나, 급한 건은 직접 입력 | 품목·재고 → 수불 입력 |
| 매일 | 마이너스 · 미달 · 이동 누락 의심 확인 → [이동 전표 만들기] | 품목·재고 → 재고 현황 / 자료 점검 |
| 품목이 바뀔 때 | ECOUNT 품목등록을 다시 올린다 (신규·변경만 반영, 없는 품목은 "숨김 후보") | 엑셀 업로드 |
| 맞춰 볼 때 | ECOUNT 재고현황을 "비교만"으로 올린다 → 품목별 차이 | 품목·재고 → ECOUNT 비교 |
| 수주가 바뀔 때 | 수주 파일 업로드 또는 직접 입력 (한 PO 여러 품번) | 수주 관리 |

업로드 안내 상자는 자료별 마지막 업로드일을 보여 주고, 매일 올리는 자료가 하루 이상 지나면 노란색으로 표시한다. 반영 직후에는 [되돌리기]가 가능하다.

### 만든 것
- **품목·재고** 메뉴(원부자재 재고 화면 대체). 탭: 재고 현황 · 수불 입력 · 수불 내역 · 발주·안전재고 · 외주 입출고 · ECOUNT 비교 · 자료 점검 · 코드 사전 · 마스터 · 예시 자료.
- 재고 엔진 `app/js/inv.js`: 현재고 = 기초재고 + 기준일 이후 수불 + 생산 반영. 결과는 `C.stock()` 형식 그대로라 대시보드·수주·MRP·AI 비서가 같은 숫자를 쓴다.
- ECOUNT 자료 인식 `app/js/ecount.js`: 품목등록 · 창고리스트 · 재고현황(범위·기준일 자동) · ERP CODE 설명 · 수불 양식. KHO NVL 장부도 수불로 바꿔 올린다(출고 = 창고→공장 이동이 기본).
- 예시 데이터는 행마다 표시(`_ex`). 화면 제목 옆에 "예시 데이터" / "예시 n행 포함"이 표시되고, 설정에서 예시 행만 지운다.
- 5차 → 6차 자동 보강: 이미 쓰던 데이터 폴더는 처음 실행할 때 ECOUNT 품목·창고·코드 사전·기초재고가 한 번만 더해진다. 기존 행은 바꾸지 않고, 5차 샘플과 똑같은 행에만 예시 표시를 붙인다. 서버는 바꾸기 전 표를 `data/backup/<날짜>/` 에 자동 백업한다.
