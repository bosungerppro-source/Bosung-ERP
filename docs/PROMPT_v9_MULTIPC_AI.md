## PROMPT

너는 BOSUNG VINA(베트남 색연필 공장) ERP를 유지보수하는 시니어 개발자다. 대부분은 스스로 판단해 적용하고 정말 필요한 것만 묻는다. 기존 기능과 숫자 정의(`docs/CLAUDE_PROMPT.md`)는 그대로 두고, 아래 문제를 **8차(v1.3.0) 위에서** 고친다.

### 1. 배경 (2026-10-19)
- 8차 검토에서 다음 차수로 미룬 것: 여러 PC 가 같이 쓸 때 저장이 서로 지워짐, 사내망 보안, PC 밖 백업, AI 비서 문제.
- 사용자: 실제 사용 때 **여러 PC 동시 사용 · 구글 시트 연동 · AI 모드**를 모두 쓴다.

### 2. 여러 PC 동시 사용 — 고칠 것과 정한 방식 (묻지 않고 정함)
| 문제 (검토에서 확인) | 고친 방식 |
|---|---|
| 두 PC 가 같은 표를 고치면 나중에 저장한 PC 가 먼저 저장한 PC 의 변경을 지움 (표 전체를 덮어씀) | 서버가 표마다 저장 번호를 둔다 (`<data>/versions.json`). 화면은 마지막으로 받은 번호를 `X-Base-Ver` 로 함께 보내고, 그 사이 다른 PC 가 저장했으면 서버가 **409 + 지금 자료**를 돌려준다. 화면은 마지막으로 서버와 맞춘 행 지문(`_base`, `_id` → 행 JSON 해시)을 기준으로 **행 단위 3-way 합치기**(`merge3`) 뒤 다시 저장한다. 한쪽만 바꾼 행은 바꾼 쪽, 둘 다 고친 행은 나중에 저장한 PC 내용(알림), 한쪽이 지우고 다른 쪽이 고친 행은 고친 행을 남긴다. `_id` 가 없는 행은 내용으로 같은 id 를 만들어 어느 PC 에서나 맞춰진다 |
| 설정(meta)도 통째로 덮어씀 (위젯 배치 · 구글 주소 · 비서 설정이 서로 지워짐) | `PATCH /api/meta {set, del}` 로 바뀐 항목만 보낸다 (화면은 `_metaBase` 와 비교). 이 PC 에서 바꾸고 아직 못 보낸 항목은 다른 PC 값으로 덮지 않는다 |
| 다른 PC 의 변경이 프로그램을 다시 열어야 보임 | 20초마다 · 창으로 돌아올 때 `/api/versions` 를 보고 바뀐 표 · 설정만 받아 합친다. 입력 · 창 · 끌기 중이 아니고 3초 넘게 손대지 않았으면 화면을 다시 그린다 (창 · 표 스크롤 유지). 아니면 왼쪽 아래 "다른 PC 변경 있음 · 새로 고침" |
| 저장에 실패하면 변경이 그냥 버려짐 ('저장 오류' 표시만) | 버리지 않고 다시 시도 (2초 → 최대 1분 간격). 실패 알림은 한 번, 다시 성공하면 "다시 저장했습니다" |
| 창을 닫을 때 보내는 중인 저장 · 설정 저장을 기다리지 않음 | `DB.flush()` 가 대기 중 · 보내는 중 · 그 사이 또 바뀐 것 · 설정 저장까지 기다린다 (Electron 은 닫기 전 최대 5초) |

### 3. 보안
| 문제 | 고친 방식 |
|---|---|
| 아무 웹사이트나 이 PC 의 ERP API 를 부를 수 있음 (DNS rebinding · 다른 출처 요청) | 모든 요청에서 Host = 이 PC 이름 · IP · localhost(+ `ERP_ALLOW_HOSTS`) 와 포트, Origin 이 있으면 같은 곳, 쓰기 요청은 `Content-Type: application/json` 만 → 아니면 403 |
| 사내망을 켜면 같은 네트워크의 누구나 모든 자료를 읽고 고침 | **사내망 PIN** (숫자 4~12자리, pbkdf2 해시 `<data>/lan.json`). 다른 PC 브라우저는 PIN 화면 → 쿠키 `erp_s` (HttpOnly · SameSite=Strict · 7일). 5번 틀리면 1분(~10분) 잠금. ERP 가 실행 중인 PC(loopback)는 PIN 없이 쓴다. **PIN 이 없으면 다른 PC 는 들어오지 못한다.** PIN 을 바꾸면 모든 세션이 끊긴다. PIN · AI 키 · 백업 설정은 ERP 가 실행 중인 PC 에서만 바꾼다 |
| 정적 파일 검사가 `app` 으로 시작하는 옆 폴더(`app2` 등)를 통과 | `appDir + path.sep` 로 검사 |
| 외부 링크가 http/https 가 아닌 주소도 엶 · ERP 창이 다른 주소로 이동할 수 있음 | http/https 만 기본 브라우저로 열고, ERP 창은 ERP 주소를 벗어나지 않는다 |

### 4. PC 밖 자동 백업
- 설정 → **사내망 접속 · 자동 백업** (또는 프로그램 메뉴 `ERP → 자동 백업 폴더 고르기…`): 폴더(USB · NAS · 구글 드라이브 동기화 폴더, 전체 경로) · 보관 개수(3~365, 기본 30) · 구글 드라이브.
- ERP 가 켜져 있는 동안 하루 한 번 (15분마다 확인, 시작 1분 뒤 첫 확인, 실패하면 30분 뒤 다시): `ERP_backup_YYYY-MM-DD.json` (같은 날은 바꿈), 보관 개수만 남긴다 (다른 파일은 건드리지 않음).
- 구글 드라이브: gzip + base64 → Apps Script `backup` (**Code.gs 3판**, 'ColorPencil ERP Backup' 폴더, 같은 이름 바꿈, 보관 개수만). 주소는 Apps Script(https · script.google.com · googleusercontent.com)만.
- 이틀 넘게 성공하지 못하면 프로그램을 열 때 알린다. 상태: 마지막 성공 · 파일 · 크기 · 마지막 오류.
- 복원: `엑셀 · 구글 연동 → 백업 / 복원` 에서 `.json` 또는 구글의 `.json.gz` 를 그대로 고른다.
- 폴더는 한 단계씩 만든다 (Node 의 recursive mkdir 은 쓸 수 없는 특수 폴더에서 끝없이 돌아 서버가 멈춘다).

### 5. AI 비서 (claude-api 자료 기준, 기본 모델 `claude-sonnet-5-5`)
| 문제 | 고친 방식 |
|---|---|
| 프로그램을 다시 열면 AI 모드가 꺼져 있음 | 키 설정을 데이터를 불러온 뒤(서버 모드를 안 뒤) 읽는다 (`ERP.aiReady → A.loadCfg`) |
| 대화가 길어지면 앞을 잘라냄 · 언어/날짜가 바뀌면 시스템 프롬프트를 다시 만듦 → Claude 의 생각 블록이 무효 (**2026-08-31 이후 만든 계정은 400 오류**), 프롬프트 캐시도 깨짐 | 대화 기록은 **뒤에 붙이기만** 한다. 시스템 프롬프트는 대화를 시작할 때 고정, 날짜 · 화면 언어 · 비서 설정이 바뀌면 질문 바로 뒤 `role: "system"` 메시지로 알린다. 너무 길면(30만 자) 앞을 자르지 않고 최근 질문 · 답 6쌍 요약으로 **새 대화**. 실패한 질문은 그 질문의 기록만 걷어낸다. 생각 블록은 바꾸지 않고 다시 보낸다 |
| 거절(`refusal`) · 잘림(`max_tokens`) 응답을 대화에 남김 | 남기지 않고 이유(안전 정책 · 분류 / 너무 김)와 내장 모드 답을 보여준다 |
| 도구 오류를 일반 결과로 보냄 · 마지막 호출에도 도구를 씀 | `is_error: true` · 8번째(마지막) 호출은 `tool_choice: {type: "none"}` |
| 요청 설정 | `max_tokens` 16000, `output_config.effort` = low(간단히) / medium(자세히), 프롬프트 캐시(시스템 블록 + 요청 위쪽 자동 캐시), **`fallbacks: "default"`** + `anthropic-beta: server-side-fallback-2026-07-01` (claude-sonnet-5-5 · opus-5-5 · opus-5 · fable-5(-1)만). 429 · 529 · 503 은 `retry-after` 만큼(최대 20초) 기다렸다가 한 번 더. 모델 · 계정이 받지 않는 선택 항목(400)은 끄고 다시 보낸다 (옛 모델: system 메시지 → `<system-reminder>`) |
| 서버 중계가 받은 요청을 그대로 넘김 (다른 PC 브라우저가 비싼 모델 · 웹 검색 같은 서버 도구를 쓸 수 있음) | 모델 = 서버 설정, `max_tokens` ≤ 16000, 정해진 필드만(`aiBody`), 서버 도구는 400, **하루 호출 한도**(기본 400, 0 = 제한 없음, ERP PC 의 비서 설정에서), 하루 사용량 기록(`<data>/ai_usage.json`, 120일: 호출 · 입력 · 출력 · 캐시 · 거절), `retry-after` 전달 |
| 도구 결과를 12,000자에서 잘라 JSON 이 깨짐 · 잘린 줄 모름 | 가장 긴 목록부터 줄이고 `<목록>_total` · `<목록>_truncated` 를 붙인다 (시스템 프롬프트에 규칙). `production_summary` · `get_po` 도 전체 개수 |
| 데모(`ERP_Demo.html`)가 API 키를 브라우저 저장소에 남김 | 이 창의 메모리에만 (새로 고치면 지워짐). 예전에 저장된 키는 한 번 읽고 지운다 |
| 설치형이 회사 프록시 · 인증서를 따르지 않음 | AI · 구글 호출은 Electron `net.fetch` (`server.start({ fetch })`) |
| 사내망 브라우저에서 비서 설정을 저장하면 403 오류 | 키 · 모델 · 한도 칸은 잠그고 내 비서 설정만 저장 |
| 내장 모드가 잘못 알아들음 | `ép lõi`(리필 성형)를 `lỗi`(불량)로 → 성조 없는 글자에서도 구분 · `생산 지연 PO` → 납기 경과 · `đã làm xong` → 완료 PO · 품번 + 재고 → 그 품목 재고 · `모자란 자재` → 안전재고 미달 · `chất lượng / phế phẩm / hàng hỏng` → 불량 · `máy nào dừng nhiều nhất` → 정지 · `sử dụng máy` → 생산 실적(공정별 가동 설비 수) · `PO tạm ngưng / 보류 / 취소` → 보류 · 취소 PO |
| MRP 에서 계산하지 못한 품번이 있어도 "모두 충분" | "계산된 항목에는 부족이 없습니다. ⚠ 항목은 계산하지 못했으니 '모두 충분'이 아닙니다" |
| AI 연결 시험 | 모델 이름 · 걸린 시간 표시, 오늘 사용량 표시 |

### 6. 지켜야 할 것
- 표를 바꿀 때는 `DB.add / addMany / update / remove / replace / upsert / touch` 를 쓴다 (직접 `DB.t[n]` 을 바꾸면 반드시 `DB.touch(n)`). 행마다 `_id`.
- 서버의 쓰기 API 는 `Content-Type: application/json` 만 받는다. 새 API 도 guard 를 거친다. 바깥 요청은 `doFetch` (Electron 은 net.fetch).
- AI 대화 기록은 뒤에 붙이기만 한다 — 중간을 고치거나 지우지 않고, 대화 중에 시스템 프롬프트 · 도구 목록을 바꾸지 않는다. 바뀐 것은 `role: "system"` 메시지로.
- 재현 시험을 먼저 만들고(고치기 전 실패 확인) 고친다.

### 8. 사용자 할 일
- 사내망을 쓰면 ERP 가 실행 중인 PC 에서 **설정 → 사내망 PIN 정하기** (정하지 않으면 다른 PC 는 들어오지 못한다. 1.3.0 에서 사내망을 켜 두었던 경우도 마찬가지).
- **자동 백업 폴더 지정** (메뉴 `ERP → 자동 백업 폴더 고르기…` 또는 설정). 구글 드라이브에도 남기려면 `google/Code.gs` 3판을 다시 배포하고 설정에서 켠다.
- AI 모드: ⚙ 에서 키를 넣고 **AI 연결 시험**. 하루 호출 한도(기본 400)를 확인한다. 거절 시 다른 모델이 답하는 `fallbacks` 가 켜져 있다 (원하지 않으면 알려 주면 끈다).
