# 12차 — 메뉴 3개 (품목 / 현장 재고 / 원부자재 재고) · ECOUNT 비교 없앰 · 이름 미정은 코드만 (2026-10-20, v1.7.0)

대상: 11차(v1.6.0) 소스. 요청 · 결정 · 규칙은 `docs/PROMPT_v12_MENUS.md`, 개발 규칙은 `docs/CLAUDE_PROMPT.md` 2-11.

## 요청 (요약)
- "품목 · 재고" 한 메뉴 안의 탭이 아니라 **왼쪽 메뉴를 품목 // 현장 재고 // 원부자재 재고** 로 나눈다 (현장 재고와 원부자재는 따로 간다).
- ECOUNT 비교는 없앤다 — 다음 달(2026-11)부터 ECOUNT 를 쓰지 않고 이 ERP 를 쓴다.
- 분류 끝의 물음표(?)와 짐작한 이름을 없앤다 — 모르면 묻는다. 답: **코드만 표시**.

## 한 일
- `p_stock.js`: 페이지 3개 (`items` · `floor` · `materials`, 같은 틀 `stockPage`), 탭 → 메뉴 표, `ERP.goStock(탭)`, 예전 `ERP.state.matTab` 요청을 맞는 메뉴로 보내는 `takeRequest` ('stock' · 'compare' 포함). 수불 입력 · 수불 내역을 그룹별로 (`txe`/`txe_floor`, `txl`/`txl_floor`, 다른 그룹 품목은 막음, 품목 목록도 그룹별), 발주 · 안전재고는 원부자재만. ECOUNT 비교 탭 삭제. 단계 카드: 이름 없으면 코드만 (물음표 없음, 말풍선 "이름 없음 — 품목 → 코드 사전"). 코드 사전: 이름 미정 줄은 빈칸 + 코드 옆 "이름 미정", 이름을 넣으면 확인됨, 다 지우면 다시 이름 미정 (다시 그리지 않음). 화면 글의 "소모품" → CM, "생산현장 재고" → "현장 재고".
- `inv.js`: 내장 사전의 짐작한 이름을 모두 비움 (단계 6 · 제품군 2 · 세부 14 · 분류 18 = 40개), `INV.label` · `labelShort` 는 이름 미정이면 코드.
- `main.js`: 메뉴 3줄 (아이콘 · 베트남어 이름), 배지는 현장 재고 / 원부자재 재고 각각, 통합 검색 묶음 이름 "품목".
- `ecount.js` · `schema.js` · `p_data.js`: ECOUNT 재고현황 "비교만" 방식 · `ecount_snap` 표 삭제, 업로드 안내 문구, 반영 결과 버튼을 올린 자료에 맞는 메뉴로.
- `p_dashboard.js`: 위젯 클릭 · 링크를 `ERP.goStock` 으로 (마이너스 재고는 원부자재에 없고 현장에만 있으면 현장 재고로), 문구 "현장 재고", 흐름 설명 "자재 → 부품 → 조립 → 포장".
- `assistant_local.js`: "원부자재 재고 열기" / "현장 재고 열기" — 재고 답변은 첫 품목이 속한 메뉴로.
- 시드(`seed.json`)의 빈 `ecount_snap` 키, `build_seed_v6.js` 의 표 이름 삭제.
- 화면 확인(캡처)에서 찾아 고친 것: 빈 값을 `Element.append` 에 넘겨 "null" 글자가 보이던 곳 — 원부자재 재고(현장 실사 안내가 없는 쪽), 공용 표 `ERP.grid` 의 빈 표, 수불 내역 · 외주 · 예시 자료 · 조립 BOM. `ERP.put(el, ...)` (core.js, 빈 값은 빼고 붙임) 추가. 단계 카드 · 재고 표의 "이동?" → "이동 누락" (물음표 없음). 코드 사전 표가 옆 칸(ERP CODE 도우미)에 잘리지 않게 이름 미정 표시를 코드 옆으로 옮기고 입력 칸을 칸 너비에 맞춤.
- 버전 1.7.0 (package.json · core.js · installer.nsi · release.yml 기본값).
- 문서: 11차 문서 · 1.6.0 출시 설명의 짐작한 이름(가공 배럴 · 소모품 · 클릭펜 …)을 코드로 고침, README · CLAUDE.md · CLAUDE_PROMPT 2-11.
