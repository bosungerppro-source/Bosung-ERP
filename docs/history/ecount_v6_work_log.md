# 6차 — ECOUNT 자료로 품목·창고·재고 재구성 (2026-10-16, v1.1.0)

대상: ColorPencil ERP 5차("나만의 AI 비서") 소스. 입력: ECOUNT 내보내기 5종(품목등록 · 창고리스트 · 재고현황 창고 "Kho thành phẩm 외" · 재고현황 공장 "SẢN XUẤT 외" · ERP CODE 설명). 상세 결정·규칙은 `docs/PROMPT_v6_ECOUNT.md`, 개발 규칙은 `docs/CLAUDE_PROMPT.md` 2-5.

## 사용자 결정
- 기존 백데이터는 예시로만 → 행마다 "예시" 표시, 설정에서 예시 행만 일괄 삭제.
- 재고 기준 = 이 ERP. ECOUNT 재고현황 = 2026-10-16 기초재고. 이후 수불은 ERP에서.
- 범위 2묶음: 창고 / 공장. 수불 = 엑셀 업로드 + 화면 입력. 생산일보 = 입고 + BOM 자재 차감.

## 한 일
- 새 파일: `app/js/inv.js`(재고 엔진·ERP CODE 사전), `app/js/ecount.js`(ECOUNT·수불 양식 인식), `app/js/p_stock.js`(품목·재고 화면, 원부자재 재고 화면 대체), `tools/build_seed_v6.js`, `tools/selftest_v6.js`.
- 시드: 품목 2,265 · 창고 11 · 코드 사전 34 · 기초재고 1,276행(창고 314 / 공장 962). 예전 샘플 표는 행 단위 예시(`_ex`).
- 5차 데이터 자동 보강(`DB.upgradeV6`): 처음 실행 때 한 번, 없는 품목·빈 표만 채우고 5차 샘플과 같은 행에만 예시 표시. 5차 백업 복원 후에도 실행.
- 업로드 화면: 자료별 안내 카드(마지막 업로드일, 매일 자료가 밀리면 노란색), 미리보기, 우선순위 순 반영, 되돌리기, 업로드 이력.
- 버전 1.1.0 (설치 파일 `ColorPencil-ERP-Setup-1.1.0.exe`).

## 남은 확인 (사용자)
- 추정 이름: CM, WIP11, WIPx5, WIPx6, WIP55, FD(→FG), GRA·MIX — 품목·재고 → 코드 사전에서 수정.
- BOM·배합표는 예시. 실제 BOM(ECOUNT 품목코드)을 넣어야 자재 차감이 정확. 그 전까지 일괄 삭제에서 BOM 표는 기본 해제.
- 실제 사용 시작일이 10-16이 아니면 그날 ECOUNT 재고현황을 "기초재고로 설정"으로 다시 올림.
