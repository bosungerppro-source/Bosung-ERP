# 18차 작업 기록 — 여러 PC 자료 공유 · 구글 드라이브 (v1.13.0, 2026-10-22)

요청 · 규칙: `docs/PROMPT_v18_CLOUD.md`.

## 요청
- "이거 직원한테줘서 직원이 입력하고 자료입력한게 업데이트 되야하는데 되지가않아 지금 자료서버가 내컴퓨터라 그런거같은데 구글시트.드라이브 연동해야돼 만들어줘. 그리고 앱스크립트 주소만들어주고 핸드폰에서 웹앱으로 볼수있게 해줘"

## 살펴본 것 (17차까지)
- PC 마다 ERP 서버가 자기 데이터 폴더 (`tables/*.json` · `meta.json` · `versions.json`) 를 쓴다.
- 9차의 여러 PC 는 "같은 서버를 여러 브라우저가" 쓰는 것이다 (사내망 접속 · PIN · 409 로 행 단위 합치기). PC 마다 따로 설치한 ERP 끼리는 자료를 주고받지 않는다.
- 구글 연동 (`p_data.js` `gpush` · `gpull`) 은 표를 통째로 바꾼다 — 두 PC 가 쓰면 마지막에 올린 PC 가 덮어쓴다.
- 이 PC 의 자료 크기 (읽기만, 2026-10-22): 표 29개 · JSON 7.7MB · gzip 0.77MB (생산 일보 21,793행 5.67MB → 539KB). `_ex` 행 없음 · `_id` 없는 행 없음 · 같은 `_id` 없음. 설정에 `gUrl` · `gToken` 없음 (구글 연동 · 휴대폰 보기 아직 안 함).
- 설치 폴더에는 `google/Code.gs` 가 없었다 (app.asar 에도 없음) — 화면 안내 "설치 폴더의 google/Code.gs" 는 맞지 않았다.

## 정한 것
- **PC 끼리 주고받기 = 구글 드라이브, 합치기 = 행 단위 (3-way)**. 구글 시트 칸에 쓰는 것은 느리고 (수만 행) 형식이 바뀌므로, 표마다 압축한 JSON 을 드라이브 파일 하나에 두고 번호로 바뀐 것만 주고받는다. 시트로 보내 보기 · 가져오기 (옛 카드) 는 그대로 둔다.
- **주고받기는 ERP 서버**가 한다 (`cloudsync.js`). 화면이 하면 창을 닫은 PC 의 입력이 남고, 사내망 브라우저마다 따로 돈다.
- **합치기 규칙은 화면 (db.js merge3) 과 같게** — 사용자가 9차부터 겪은 "같은 행을 두 PC 가 고치면 나중에 저장한 PC 내용" 과 같은 결과.
- **이 PC 에만 두는 설정**: 구글 주소 · 키, 휴대폰 보기 켜짐, AI 비서 프로필, 종합 현황 배치 (1.12.5 사용자 배치는 사장님 것 — 직원 PC 는 기본 배치 = 같은 배치), 붙여넣기 숫자 형식 (베트남어 PC 는 1.234,5), MRP 입력 줄.
- **처음 연결**: 사장님 PC = 올리기, 직원 PC = 구글 자료로 (예시 자료로 처음 켠 ERP — 이 PC 자료는 백업). 직원이 이미 자기 PC 에 입력해 둔 자료가 있을 수 있어 "이 PC 에만 있는 자료도 더하기" (미리 보기) 를 두었다. 예시 행 · 같은 코드의 품목 (시드 사본) 은 더하지 않는다.
- **Apps Script 주소**: 구글 계정 로그인 · 권한 승인은 사용자만 할 수 있다. 그래서 ERP 가 비밀 키를 만들어 넣은 코드를 [Apps Script 코드 복사] 로 주고, 카드에 순서를 적었다 (새 구글 시트 → 확장 프로그램 → Apps Script → 붙여넣기 → 배포 → 웹 앱 → 액세스 승인 → URL 붙여넣기). 직원 PC 는 연결 코드 (`ERPC1.…`) 하나만 붙여넣는다.
- **휴대폰**: 15차의 휴대폰 보기가 같은 웹 앱 주소에 이미 있다 (5판에 그대로). 웹 앱을 배포하고 설정 → 휴대폰으로 보기에서 비밀번호를 정하면 된다.

## 1.13.2 (2026-10-23) — 구글 시트 = 공유 자료 보기 (Code.gs 6판)
- 사용자 (2026-10-23): "1.13.2 구글 시트 표 보기 작업 이어서 마무리해줘"
- 이어받은 것: 1.13.1 다음에 시작한 작업이 커밋되지 않은 채 있었다 — `google/Code.gs` 6판 (`cloud_sheet` · 탭 쓰기 · 안내 탭 · 보낸 PC · `L_` 레이아웃) 과 `server.js` (`loadLayouts` · `/api/cloud/sheet` · cloudsync 에 `layout` · `pc`). `cloudsync.js` · 화면 · 시험 · 문서는 없었다. 작업 PC 가 바뀌어 (Windows 사용자 gd → Admin) 처음 요청 원문은 남아 있지 않다. 이어받은 그대로의 사본: 작업 폴더 `05_backup/wip_1.13.2_2026-10-23/`.

### 확인한 것
- 이 PC 자료 (1.13.1 적용 전 백업, 읽기만): 표 29개 중 행이 있는 표 11개 — 생산 일보 21,793행 (화면 34열 + 다른 칸) · 재고 수불 · 배합표 · 품목 · 수주 · 기초재고 · 업로드 이력 · 해외 주문 · 거래처 · 코드 사전 · 따로 관리 재고. 빈 표 (`ecount_snap` · `movements` 등) 는 올리지 않으므로 탭도 없다. 칸 수는 합쳐 100만 안팎 — 구글 시트 한도 (1천만) 안.
- schema.js 를 server.js 처럼 (Node vm) 읽으면 표 27개 모두 한국어 이름 · 머리글. 레이아웃 JSON 은 표마다 최대 1,200자 (스크립트 속성 9KB 안).
- 옛 "시트로 보내기" (2판~) 는 영어 표 이름 탭 (`po`), 6판은 한국어 이름 탭 (`수주 (PO)`) — 겹치지 않는다.
- 이어받은 6판 코드의 문제 (새 시험으로 확인, 고치기 전 실패 10개):
  1. 저장 (`cloud_put`) 응답이 시트 쓰기가 끝날 때까지 기다림 (사용자 잠금 240초까지) — 큰 표는 저장마다 수십 초, 그동안 그 PC 의 주고받기가 막힌다.
  2. `=IMPORTDATA("http://x")` 같은 입력이 시트에서 수식이 됨 — 시트가 바깥 주소로 자료를 보낼 수 있다.
  3. 한 표에서 오류 (칸 한도 등) 가 나면 시트 갱신 전체가 실패하고, 저장할 때마다 같은 오류를 되풀이.
  4. 모두 다시 쓰기 (`all`) 가 시간 한도로 끊기면 남은 표를 다시 쓰지 않음 · 지운 탭은 그 표가 다시 저장될 때까지 없음.

### 정한 것
- 저장과 시트 쓰기를 뗐다: `cloud_put` 은 저장 번호만, 시트는 `cloud_sheet` — ERP 가 주고받기 (`exclusive`) 밖에서 따로 부른다. 직원 PC 로 자료가 넘어가는 시간 (18차의 핵심) 이 시트 쓰기에 묶이지 않게.
- 모아서: 보낸 뒤 20초 (잇따라 저장해도 20초마다 한 번) — 생산 일보처럼 큰 표를 저장마다 다시 쓰지 않게.
- 다른 PC 가 못 한 갱신 (저장하고 바로 끔 등) 은 뒤처진 지 1분 뒤 다른 PC 가 대신 — 시트가 오래 옛 자료로 남지 않게.
- 오류 표는 그 표만 (번호와 함께 기억, 새로 저장되면 다시). ERP 요청 실패는 1분 · 2분 … 30분 뒤.
- 문서 잠금 10초 (이어받은 코드의 사용자 잠금 240초 대신) — 기다리는 실행이 Apps Script 실행을 오래 잡지 않게. 못 잡으면 `busy`, ERP 는 20초 뒤 다시.
- 5판 · 시트 없는 스크립트는 시트 갱신을 부르지 않고 화면에서 안내 (자료 공유는 그대로).
