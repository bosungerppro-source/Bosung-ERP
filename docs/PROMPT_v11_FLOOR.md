## PROMPT

너는 BOSUNG VINA(베트남 색연필 공장) ERP를 유지보수하는 시니어 개발자다. 대부분은 스스로 판단해 적용하고 정말 필요한 것만 묻는다. 기능과 숫자 정의는 그대로 두고, 아래를 **10차(v1.5.0) 위에서** 한다.

### 1. 사용자 요청 (원문, 2026-10-20 · 첨부: `bom 사용량.xlsx`, `TỒN KHO 20.10.2026.xlsx`)
> 이건 bom사용량 오래된버전이라 나중에 최신으로 업데이트할수있게 설정해줘. 공정중 부품과 색연필조립형태의 현장 재고이다.
> wip00+wip01+wip02+wip0x=wip 이고 wip11+wip21+wipx1=wip01 이런 규칙이다. 너가 분석해서 반영해줘.
> 공정중 재고는 원부자재 재고와 분리하고 bom에서 차감되는 재고는 현장재고만이고 원부자재 재고는 절대로 건들지 않는다.

### 2. 자료 분석
- **현장 재고 실사 (TỒN KHO)**: 시트 3개 — `Assy`(조립품 WIP · WIP55), `Refill`(심 WIP00), `Injection`(배럴 WIP01 · 노즈콘 WIP02 · 홀더/플러그 WIP03 · 스푼 WIP04, 그리고 부자재 SM 1행). 열 = `Mã mặt hàng · Tên mặt hàng · ERP CODE · Thông số · SẢN XUẤT`, 시트 끝에 `TOTAL`. 날짜는 파일 이름에만 있다 (`20.10.2026`).
- **BOM 사용량 (`components` 시트)**: `code · item code · color · 향기오일(글자) · 원료 50여 열(g/개)`. 385행(제품군 BM · BR · BP · RB · P · BIC), 한 행의 합계 0.6 ~ 3.7 g = 심 1개의 배합. 같은 code 가 두 번 나오는 것 59개(값이 다름).
- **ECOUNT 품목(10-16)**: WIP11 = 핫포일(HF) 배럴 220개(AB101 …). 조립품이 WIP11 배럴을 바로 쓴다 (BM01002 = 심 RM102 + 배럴 AB102 + 홀더 MH + 스푼 MS). WIP21 은 아직 없다. ECOUNT 의 ERP CODE 설명에는 WIP11 정의가 없다 (7차의 WIP11 이름은 추정이었다 — 12차에서 지우고 코드만 표시).

### 3. 확정한 해석 (묻지 않고 정한 것)
1. `wip00+wip01+wip02+wip0x=wip` — 조립품(WIP) 1개 = 심(WIP00) + 배럴(WIP01 계열) + 노즈콘(WIP02) + 그 밖의 WIP0x 부품(홀더 · 스푼 …). 조립 BOM 자동 구성의 역할(심 · 배럴 · 노즈콘 · 홀더 · 스푼)과 같다.
2. `wip11+wip21+wipx1=wip01` — WIP11 · WIP21 · … · WIPx1 은 모두 **배럴(WIP01) 계열**이다 (조립품에는 그중 하나가 배럴로 들어간다). 새 단계 `WIPx1`(WIP21 · 31 …, 이름 미정), WIP11 은 그대로. 조립 BOM 의 배럴 후보 순서 = WIP11 → WIPx1 → WIP01. 생산현장 흐름 카드에 WIP11 · WIPx1 카드.
3. 공정 중 재고는 원부자재와 분리 — 현장 실사(TỒN KHO)가 공정 중(WIP 단계) 품목의 기초재고이고 기준일도 따로(`meta.openDate.FLOOR`). ECOUNT 재고현황은 원부자재 · 포장품(마니라 · 박스)의 기초. 서로 지우지 않는다.
4. BOM 으로 차감하는 것은 현장 재고뿐, 원부자재는 절대 안 건드림 — 생산 반영이 원재료 · 부자재 · CM 을 줄이던 길을 모두 막는다: 사출 수지(일보의 `raw_kg`), 배합표(리필 원료 g/개), BOM 라인에 들어 있는 원부자재. 진단(`diag.matSkip`)에만 남긴다. 원부자재는 수불(입고 · 출고 · 이동 · 조정)로만 바뀐다.
5. "BOM 사용량은 옛 판, 나중에 최신으로" — 배합표(`recipes`)로 올리고 기본 반영 방식 = **전체 교체**: 최신 판을 올리면 통째로 바뀐다. 지금 쓰는 파일 · 올린 날 · 품목 수 · 중복 코드를 배합표 탭에 보인다. 재고 차감에는 쓰지 않고 MRP · 신고서 계산에만 쓴다.
6. TỒN KHO 의 부자재(SM) 행과 TOTAL 행은 넣지 않는다 (미리보기에 "제외"). 마니라 · 박스(SG · FG) · ERP CODE 없는 행도 현장 실사에서 뺀다.
7. 배합표에서 같은 code 가 두 번이면 첫 행을 쓰고 중복 목록을 보인다 (최신 판에서 확인).
8. WIP06 계열(WIP06·x6)은 조립 BOM 역할에 넣지 않았다 (어느 부품이 1자루에 들어가는지 모름) — 필요하면 BOM 편집에서 직접 넣는다.

### 4. 데이터 · 계산 규칙
- **현장 실사 행**: `stock_open` 에 `grp: 'floor'` (scope FAC, `file` · `sheet` 기록), 기준일 `meta.openDate.FLOOR`. `INV.opening()` 의 `floor` · `n.FLOOR` · `date.FLOOR`, `INV.floorActive()`, `INV.openDateFor(item)`, `INV.inProcess(x)`, `INV.WIP_STAGES`, `INV.BARREL_STAGES`, `INV.isBarrel(st)`.
- **현장 실사가 있을 때 공정 중 품목**: 기초 = 현장 실사 행만 (ECOUNT 의 같은 품목 숫자는 쓰지 않음), 기준일 = 현장 실사일 (수불 · 생산 반영 모두 그다음 날부터). 그 밖의 품목은 ECOUNT 기준일(창고 · 공장).
- **현장 실사 다시 올리기**: 다른 파일 · 다른 기준일의 현장 실사 행은 모두 지우고, 같은 파일 · 같은 기준일의 다른 시트 행은 남긴다 (여러 시트를 차례로 반영). 품목 마스터에 없는 코드는 ERP CODE 로 품목을 만든다 (`src: 'floor'` — 뒤에 ECOUNT 품목등록이 갱신할 수 있음).
- **ECOUNT 재고현황 "기초재고로 설정"**: 같은 범위의 `grp: 'floor'` 행은 지우지 않는다. 미리보기에 "공정 중 품목 N개는 현장 실사 수량을 그대로 씀".
- **생산 반영 (`INV.postRows`)**: 가장 이른 기준일 다음 날부터 보고, 행마다 그 품목의 기준일(`openDateFor`) 다음 날인 것만 PROD · USE. 원부자재 USE 는 없다 (`isMatItem` · 원료 kid · 사출 수지 → `diag.matSkip` 코드별 행 · 수량). 반영 방식 이름 = "생산량 입고 + BOM 현장 부품 차감 (원부자재 제외)".
- **BOM 사용량 인식 `recipes_usage`**: 머리글 첫 칸 `code` + `item code` + `color`. `열N` · 빈 이름 열은 빼고, 글자만 있는 열(향기오일 이름)은 비고(`note`), 0 · 빈 칸은 행을 만들지 않음. 기본 `replace`(또는 `upsert`). 반영 뒤 `meta.recipeSrc = {file, at, products, rows, dups, mode}`. 읽는 열 수 90.
- **업로드 화면**: `job.onFile(j)` (파일 이름을 안 뒤 — 현장 실사 기준일), 현장 실사 기준일 입력 칸(같은 파일의 시트에 같이 적용), 기준일 없으면 반영 안 함, 이전 실사를 바꿀 때 확인, 되돌리기에 품목 포함. `XL.apply` 는 반영 뒤 `job.after(job, res)` 를 부른다.
- **업그레이드 `DB.upgradeV11`**: ERP CODE 가 `WIP[2-9]1-` 인데 단계가 WIPx1 이 아닌 품목을 다시 분류 (`meta.v11`). 시작할 때 · 백업 복원 뒤.
- **표**: `stock_open` 에 `grp` · `sheet` 열, `recipes` 에 `note` 열.

### 5. 지켜야 할 것
- 원부자재는 생산 반영으로 절대 차감하지 않는다 — 새 BOM 출처를 더할 때도 `isMatItem` 으로 거른다.
- 현장 실사와 ECOUNT 기초재고는 서로 지우지 않는다.
- 공개 저장소다: 공장의 실제 엑셀(현장 실사 · 배합표 · 수량)은 저장소에 넣지 않는다. 시험은 코드로 만든 가짜 엑셀을 쓴다.
