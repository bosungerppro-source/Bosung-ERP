## PROMPT

너는 BOSUNG VINA(베트남 색연필 공장) ERP를 유지보수하는 시니어 개발자다. 대부분은 스스로 판단해 적용하고 정말 필요한 것만 묻는다. 기존 기능과 숫자 정의(납기 경과 60일 등, `docs/CLAUDE_PROMPT.md`)는 그대로 두고, 아래 문제를 **7차(v1.2.0) 위에서** 고친다.

### 1. 배경 (2026-10-19)
- 계정을 옮기면서 v1.2.0 전체를 코드 검토(재고 계산·ECOUNT / 엑셀 업로드·화면 / AI 비서)했다. 기존 자동 시험은 문서에 적힌 경우만 확인해서, **실제 현장 엑셀을 넣으면 입력이 사라지거나 숫자가 틀리는 문제**를 잡지 못했다.
- 사용자: 아직 시험 단계. 실제 사용 때 구글 시트 연동 · AI 모드 · 여러 PC 동시 사용을 모두 쓴다. Windows 설치·실행은 정상.
- 출시 계획: v1.3.0 데이터 정확성(이 문서) → v1.4.0 여러 PC · 보안 · 백업 · AI 비서 → v1.5.0 부품 업데이트 · 설치 파일.

### 2. 고칠 것과 정한 방식 (묻지 않고 정함)
| 문제 (검토에서 확인) | 고친 방식 |
|---|---|
| 같은 날 같은 공정의 일보를 하나 더 올리면(주간/야간, 1층/2층) 먼저 올린 기록이 지워짐 | 일보 · ERP 양식 행은 **날짜 · 공정 · 출처 · 조 · 작업장**이 모두 같을 때만 바꾼다. `prod_log.workplace`(작업장) 열 추가 = 일보의 "1. 작업장명" 칸. 조 = 시트 이름(Ca ngày / Ca đêm · Day / Night · 주간 / 야간) → 행의 DAY/NIGHT 칸 → D. 작업장이 없는 예전(1.2.0) 행은 같은 일보로 본다 |
| 누적 시트(Ho_so)와 일보가 같은 날짜에 둘 다 들어가 두 번 셈 | 같은 날짜 · 공정의 누적 시트(`source:'history'`) 행이 있으면 일보 행은 **기본으로 건너뛰고** 미리보기에 알린다. "일보로 바꾸기"(`job.overlapMode='replace'`)를 고르면 그날 누적 행 대신 일보 행. 누적 시트를 올리면 지금처럼 공정 · 기간 전체를 바꾼다 |
| 수주(PO) 엑셀을 올리면 키가 같은 다른 줄이 하나로 합쳐짐 (521줄 → 513줄) | `po.nat` = po_no · po_no2 · item_no · date · kind · kind2 · color, `po.multi = true` → `DB.upsert` 가 같은 키 줄을 **순번으로** 맞춘다 (파일의 n번째 ↔ 기존의 n번째). 품목 같은 마스터 표는 지금처럼 합친다 |
| 취소 · 보류 PO(Condition: Cancle / cancle / Di hold)를 진행 중 · 납기 경과로 셈 | `C.poCond(p)` → 'cancel' · 'hold'. 표시가 있으면 줄 상태 = cancel/hold (포장이 끝났어도). `C.isOpen(o)` = 완료 · 취소 · 보류가 아님 → 대시보드 · 배지 · 비서 · MRP 가져오기가 같이 쓴다. PO 상태: 모든 줄이 취소/보류면 PO 도 취소/보류, 아니면 취소 · 보류 줄을 뺀 줄로 계산. 수주 관리에 "취소 · 보류" 탭 |
| KHO NVL 입출고장을 올리면 카톤 · 마니라가 완제품 재고로 들어감 (5,534줄 중 392줄) | `INV.ledgerToTx` 순서: ① 창고코드가 원부자재 품목 ② 품번이 원부자재 품목 ③ Mã XNK 후보(예: R-430VN 카톤 117종)를 품번 앞부분(52-9824-0)과 품명으로 좁힘 ④ VN 접미어. 원부자재가 아니면 넣지 않고 "코드 확인"으로 고르게 한다 |
| ERP 의 "일보 양식 받기" 양식을 채워 올리면 엉뚱한 표로 들어감 | `XL.dailyTemplateBook()` (시트 `prod_<공정>`) + 전용 인식기 `erp-daily` → 그 공정의 생산일보, 조 = 주/야 칸, 기간 교체. 빈 줄 · 예시 줄은 건너뜀 |
| 글자 날짜(17/10/2026)가 저장되어 재고에서 조용히 빠짐 | 공용 `ERP.fmt.parseDate` (Date · 엑셀 날짜 숫자 · ISO · d/m/y 일 먼저(앞자리가 13 이상이면 월 먼저) · dd.mm.yy). 수불 양식 · 입출고장 · 붙여넣기 · 일보 날짜에 사용. 못 읽은 날짜는 버리지 않고 미리보기에 "날짜를 읽지 못함"으로 보이고 반영하지 않는다. 일보에서 생산일자를 못 찾으면 오늘로 넣지 않고 날짜를 넣게 한다 |
| 파일명 날짜 해석이 "…2026-10-08" 을 2008-10-26 으로 읽음 | `XL.fileDate`: ISO 먼저, 그다음 일-월-년 |
| 기초재고 기준일이 행 하나의 날짜로 바뀜 · 기준일 당일 입력이 경고 없이 무시됨 · [이동 전표 만들기]가 두 번 만들어짐 | 기준일은 범위마다 `meta.openDate` 에 저장(ECOUNT 재고현황을 "기초재고로 설정"할 때). 예전 자료는 처음 실행 때 행 날짜 최댓값으로 한 번 채움(`DB.upgradeV8`). 수불 입력에서 기준일 당일 · 이전이면 "재고에 반영되지 않음" 경고 + 저장 확인. 자동 이동 전표 날짜 = `INV.suggestDate()` (오늘, 단 기준일 당일 · 이전이면 다음 날) |
| 베트남어 PC 에서 엑셀 숫자를 붙여넣으면 35.000 이 35 로 들어감 | 공용 `ERP.fmt.parseNum` (35.000 · 35,000 · 1.234,5 · (1,000) · −120 · '2 200'). 애매한 1.234 는 이 PC 의 숫자 형식(Intl), 설정 "붙여넣기 숫자 형식"(자동 / 1,234.5 / 1.234,5)으로 바꿀 수 있다. 생산 · BOM · 수불 붙여넣기에 사용 |
| PO 편집에서 한 줄만 고쳐도 다른 줄의 수주일 · 납기가 첫 줄 값으로 바뀜 | 기존 줄에는 사용자가 바꾼 머리글 칸만 반영 |
| 이미 BOM 이 있는 품목에 "새 조합 만들기"를 하면 부품이 두 번 차감됨 | 품목 코드를 넣으면 기존 구성을 불러오고, 저장할 때 그 품목의 기존 줄(자동 포함)을 바꾼다 |
| 구글 시트로 올렸다 가져오면 코드가 바뀜 (0414210300 → 414210300, 523034E200 → 5.23034e+205) | 올릴 때 열 종류(`types`)를 보낸다. `google/Code.gs` 2판: 숫자 · 참거짓이 아닌 열은 일반 텍스트(@) 형식으로 먼저 바꾼 뒤 쓴다, ping 에 `ver: 2`. 옛 스크립트면 화면에서 다시 배포하라고 알린다 (**사용자가 Apps Script 를 다시 배포해야 함**) |
| 수불 입력에서 검사에 걸린 줄이 저장 뒤 사라짐 | 저장한 줄만 빼고 나머지는 입력표에 남김 |

### 3. 정확도 개선
- **포장 일보**: 열 0 = 제품명/고객 품번, 1 = 완제품(FG, CT) 코드, 2 = 마니라(SG, SET) 코드. `code` = 그 PO 의 품번과 같은 값(열 1 → 열 0), 새 열 `item`(재고 품목코드) = 완제품 코드, 새 열 `ok_ct` = 실적 CT. 생산 반영(`INV.postRows`)은 `item` → `code` → `code_map` 순, CT 품목은 일보의 CT 가 있으면 그대로 입고. 종이권취 일보의 CT(열 13)도 `ok_ct`.
- **조립 · 스탬핑 일보 품목군**: 누적 시트의 같은 코드 → ERP CODE 제품군별 누적 시트 최빈값(MINI→Mini, REG→Dial …) → 설비 이름. ("Regular" 행이 따로 생기던 문제)
- **설비 대수**: `C.machKey(r)` = 공정 + 종류 + 번호 (종류 = 설비명에서 Assy · M/C 를 뺀 것, 없으면 품목군). Mini 1번 ≠ Regular 1번. 설비 탭은 마스터에 설비명 · 품목군이 있으면 종류까지 맞춰 센다.
- **MRP "전체 품번"**: `ERP.poMrpLines(po)` = 진행 중인 줄의 남은 수량만.
- **사출 원료**: 사용자 연결(code_map raw)이 이름 매칭보다 먼저. 양품 0 이어도 원료 kg 차감.
- **캐시**: 생산 반영 · 재고 캐시 키에 기준일 · 공정 단위 포함 (설정만 바꿔도 다시 계산).
- **ECOUNT 품목 재업로드**: 직접 만든 품목(`src:'local'`)은 바꾸지 않고 미리보기에 표시.
- **되돌리기**: 업로드 이력(`uploads`)까지 되돌림.
- **수불 양식 이동**: 출발 · 도착 중 빈 칸은 반대 범위로 채우고 미리보기에 표시.
- **포장 BOM**: 같은 품번 BOM 이 없어 비슷한 품번의 구성을 쓰면 `diag.similar` → 생산 반영 탭에 "확인 필요".
- **자동 BOM 일괄 적용**: 모든 부품이 확실한(초록) 품번만. 행별 적용은 노랑 부품을 모두 고른 뒤에만.
- **데모 자료** (`tools/fix_seed_v8.js`): 누적 시트와 겹치는 일보 46행(10-08 조립 18 · 포장 4 · 리필 8 · 8월 10일로 잘못 들어간 종이권취 16) 삭제, PO 머리글 행 삭제, `_meta.openDate`. 10월 조립 합계 2,901,329 → **2,615,099**.

### 4. 지켜야 할 것
- 사용자 입력 · 엑셀에서 날짜 · 숫자를 읽을 때는 `ERP.fmt.parseDate` · `ERP.fmt.parseNum` 을 쓴다 (엑셀의 진짜 숫자 칸은 지금처럼 숫자 그대로).
- "진행 중 PO" 는 `C.isOpen` 으로 판단한다 (`st !== 'done'` 만으로 판단하지 않는다).
- 일보 행에는 `source`('daily-report' · 'template' · 'history' · 'manual'), `shift`, `workplace` 를 넣는다. 일보 교체는 이 다섯 칸(날짜 · 공정 · 출처 · 조 · 작업장) 기준이다.
- 재현 시험을 먼저 만들고(고치기 전 실패 확인) 고친다.
