# ColorPencil ERP — 18차 개정 프롬프트: 여러 PC 자료 공유 — 구글 드라이브 (v1.13.0 ~ 1.13.2)

## PROMPT

너는 BOSUNG VINA(베트남 색연필 공장) ERP를 유지보수하는 시니어 개발자다. 기능과 숫자 정의는 그대로 두고, 아래를 **17차(v1.12.x) 위에서** 한다. 이름 · 글자를 짐작해서 쓰지 말고, 모르면 사용자에게 묻는다.

### 1. 사용자 요청 (원문, 2026-10-22)

> 이거 직원한테줘서 직원이 입력하고 자료입력한게 업데이트 되야하는데 되지가않아 지금 자료서버가 내컴퓨터라 그런거같은데 구글시트.드라이브 연동해야돼 만들어줘. 그리고 앱스크립트 주소만들어주고 핸드폰에서 웹앱으로 볼수있게 해줘

- 17차까지: PC 마다 설치한 ERP 는 자기 데이터 폴더만 쓴다. 다른 PC 와 같은 자료를 쓰는 길은 9차의 사내망 접속 (같은 네트워크의 브라우저가 이 PC 의 ERP 를 엶) 뿐이었다.
- 구글 연동 (Code.gs 2판 ~ 4판) 은 표를 구글 시트로 통째로 올리기 · 가져오기 (마지막에 올린 PC 가 덮어씀) · 드라이브 백업 · 휴대폰 요약뿐이었다.
- 그래서 직원 PC 에 ERP 를 설치해 입력해도 사장님 PC 에 들어오지 않았다.

**1.13.1** — 1.13.0 결과를 듣고, Apps Script 배포를 같이 하자며 덧붙였다.

> 같이하고. erp파일은 지원여러명이서 입력하고 사용하는거다. 직원들이 올리는자료는 한곳에 업로드되고 업데이트되야하고 다같이 erp파일설치해서 보고 확인하고 업로드해야되

- 직원 여러 명이 각자 ERP 를 설치해 입력 · 업로드하고, 모두 한 곳(구글 웹 앱 하나)으로 모여 모두에게 업데이트된다 — 1.13.0 의 구조 그대로 (PC 대수 제한 없음).
- PC 가 여러 대면 30초마다 묻는 `cloud_info` 가 스크립트 속성 하루 한도에 가까워질 수 있어, 배포 전에 구글 쪽 코드를 고쳤다 (아래 2-1).

**1.13.2** — 구글 시트 = 공유 자료 보기 (Code.gs 6판).

> 1.13.2 구글 시트 표 보기 작업 이어서 마무리해줘 (2026-10-23)

- 1.13.1 다음에 시작한 작업 (Code.gs 6판 · server.js 의 표 이름 · 머리글) 이 커밋되지 않은 채 남아 있었다. 작업 PC 가 바뀌어 처음 요청 원문은 남아 있지 않다. Code.gs 머리말의 설계: "이 스프레드시트 = 공유 자료 보기 — 표마다 탭 (ERP 화면과 같은 한국어 이름 · 머리글) + 맨 앞 ERP 자료 안내, 어느 PC 가 저장하든 갱신, 고치는 것은 ERP 에서".
- 그 설계대로 마무리했다. 다만 저장 응답이 시트 쓰기를 기다리던 것을 따로 떼고, 오류 표 · 수식 · 지운 탭을 처리했다 (아래 2-12).

### 2. 확정한 규칙

1. **여러 PC 자료 공유 = 구글 드라이브 (Apps Script 웹 앱 하나)** — `cloudsync.js` (ERP 서버) · `google/Code.gs` 5판 · 화면 `app/js/cloud.js`.
   - 주고받기는 화면이 아니라 PC 마다 ERP 서버가 한다. 어느 화면을 보든, 사내망 브라우저가 몇 개든 하나만 돈다.
   - 구글 쪽: 표마다 드라이브 파일 하나 (`ColorPencil ERP Data/<표>.json.gz.b64` — ERP 가 보낸 gzip + base64 글자 그대로).
   - 스크립트 속성 `T_<표>` = {저장 번호 v, 파일 f, 글자 수 s, 행 수 n, 시각 at}. 설정(공유 항목)은 표 이름 `__meta`.
   - 저장소 이름표 `CLOUD_ID` — 웹 앱 주소가 바뀌어도 같은 저장소인지 안다. 다른 저장소면 `CID` 오류로 멈추고 다시 연결하게 한다.
   - `cloud_info` (번호만) → 바뀐 표만 `cloud_get` / `cloud_put`.
   - `cloud_put` 은 ERP 가 마지막으로 본 번호(base)가 지금 번호와 같을 때만 쓴다. 잠금(LockService) 안에서 파일을 먼저 쓰고 번호를 나중에 올린다 → 읽기는 잠금 없이도 번호보다 옛 내용을 받지 않는다.
   - 번호가 다르면 conflicts → ERP 가 받아서 합친 뒤 다시 보낸다 (4번까지).
   - 같은 파일을 고쳐 쓴다 (`setContent`, 10MB 까지). 9,000,000 글자가 넘으면 새 파일을 만들고 옛 파일은 휴지통.
   - 시트 없이 만든 스크립트(독립형)에서도 공유는 된다 (시트 보내기 · 가져오기만 안 됨). `'CHANGE-ME'` 키 그대로는 아무 요청도 받지 않는다.
   - **번호 목록 캐시 (1.13.1)**: `cloud_info` 의 답(이름표 · 표마다 번호)은 스크립트 캐시 `CLOUD_IDX` 에 10분. PC 여러 대가 30초마다 물어도 스크립트 속성 (일반 구글 계정 하루 읽기 · 쓰기 5만 번) 을 쓰지 않는다.
     - 캐시를 채우고 바꾸는 것은 언제나 잠금 안에서 속성을 읽은 뒤 (쓰기 사이에 옛 목록이 끼지 않게). `cloud_put` 은 끝날 때 (도중에 멈춰도) 캐시를 속성과 같게 한다.
     - 캐시에 못 쓰면 지운다 → 다음 물음은 속성에서. `cloud_get` 은 언제나 속성 (파일 id).
2. **합치기 = 화면(db.js, 9차)과 같은 3-way merge** — 행 `_id` 와 지문(cyrb53).
   - 기준 = 마지막으로 구글과 맞춘 행 지문 (`<data>/cloud/<표>.json`).
   - 한쪽만 바꾼 행은 바꾼 쪽. 둘 다 고친 행은 이 PC 내용 (= 나중에 맞춘 PC 가 남음, 상태에 충돌 수). 한쪽이 지우고 다른 쪽이 고친 행은 남긴다.
   - 이 PC 의 표를 읽고 · 합치고 · 쓰는 동안 await 가 없다 (화면 저장은 409 로 다시 합침).
   - `_id` 가 없는 행은 화면과 같은 id. 같은 `_id` 가 또 나오면 뒤의 것은 `_id~순번` (합칠 때 행이 사라지지 않게).
3. **설정(meta)은 항목별로 합친다.**
   - **이 PC 에만 두는 항목** (`LOCAL_META`):
     - `gUrl` · `gToken` — 구글 주소 · 키.
     - `mobileOn` — 휴대폰 요약은 켠 PC 가 보낸다.
     - `ai*` — AI 비서 프로필.
     - `dash` · `dashAsmMonthly` — 종합 현황 배치. 직원 PC 는 기본 배치 (= 1.12.5 사장님 배치).
     - `numFmt` — 붙여넣기 숫자 형식 (PC 의 엑셀 형식).
     - `mrpLines` — MRP 입력 줄.
     - `cloud*`.
   - 나머지 (공정 `procs` · 기초재고 기준일 `openDate` · 리드타임 `buyLead` · 피벗 표 `floorPivots` · 수주 종류 · `seeded` 등) 는 공유.
4. **언제**
   - 30초마다 `cloud_info` 한 번 (바뀐 것이 없으면 그것뿐).
   - 이 PC 에서 저장한 뒤 3초 (`PUT /api/t` · `PATCH /api/meta` → `cloud.poke()`).
   - ERP 를 끄기 전: `electron/main.js` `flushAll` — 창 닫기 · 업데이트 설치 · 사내망 재시작 때 보낼 것이 있으면 최대 15초.
   - 실패하면 30초 × 2ⁿ (최대 5분) 뒤 다시.
   - 직원 PC 에서 입력 → 보통 1분 안에 사장님 PC 화면 (서버 30초 + 화면 20초 poll).
5. **처음 연결 (모드)** — 이 PC 에서만 (loopback). 다른 PC 브라우저는 상태 보기 · 지금 맞추기만.
   - `upload` — 구글이 비었을 때 이 PC 자료를 올린다 (사장님 PC, 처음 한 번). 빈 표는 올리지 않는다.
   - `replace` — 구글 자료로 (직원 PC · 새 PC).
     - 이 PC 자료는 먼저 `<data>/cloud_backup/<시각>_replace/` 에 복사한다.
     - 구글에 없는 이 PC 의 표는 그대로 둔다 (고치면 올라감). 설정은 공유 항목만 구글 것.
   - `merge` — 이 PC 에만 있는 행을 더한다 (미리 보기: 표마다 더할 행 수).
     - 예시(`_ex`) 행 · 같은 `_id` · 같은 내용 · 같은 기준 키 (반복 없는 표의 `nat`, 화면이 보냄) 는 더하지 않는다.
     - 설정은 구글 값이 이기고, 구글에 없던 항목은 더한다.
   - `overwrite` — 구글을 이 PC 자료로. 다른 PC 는 다음에 맞출 때 따라온다 (그 PC 에서 아직 보내지 않은 입력만 남음).
   - `resume` — 꺼 둔 뒤 다시 켬. 꺼 둔 동안 양쪽 변경을 합친다 (이름표가 같고 기준이 있을 때).
6. **안전**
   - 이 PC 의 표가 절반 아래로 줄면 (100행 이상) 쓰기 전에 그 표를 `cloud_backup/<시각>_shrink_<표>/` 에 복사하고 화면에 알린다 (최근 20개).
   - 표 파일을 읽을 수 없으면 (깨짐) 빈 표로 보지 않고 멈춘다 (`LOCAL` 오류 — 구글 자료를 지우지 않게).
   - 맞춘 적 있는 표의 파일이 없어지면 구글 자료로 되살린다.
   - 공유 중에 자료를 통째로 바꾸는 버튼 (샘플 데이터로 초기화 · 전체 삭제 · 백업 복원 · 시트에서 가져오기) 은 확인 글에 "다른 PC 의 자료도 똑같이 바뀝니다" (`ERP.cloudWarn`).
7. **비밀 키 (TOKEN)**
   - [Apps Script 코드 복사] 는 키가 없거나 16자보다 짧으면 새로 만든다 (24바이트 무작위, base64url 32자) → 이 PC 설정 `gToken`.
   - 복사하는 코드 = `google/Code.gs` 에서 `var TOKEN = 'CHANGE-ME';` 한 줄만 바꾼 것 (`POST /api/cloud/code`, 이 PC 만).
   - 직원 PC 연결 코드 = `ERPC1.` + base64url({u: 웹 앱 주소, t: 키}). 직원에게만 준다.
   - 키 · 코드 · 연결 코드는 저장소에 올리지 않는다 (공개 저장소).
8. **Apps Script 주소는 사용자가 만든다** — 구글 계정 로그인 · 권한 승인 (액세스 승인 → 고급 → 이동 → 허용) 은 사용자만 할 수 있다. ERP 카드의 순서:
   1. [Apps Script 코드 복사].
   2. 새 구글 시트 (sheets.new) → 확장 프로그램 → Apps Script → 원래 코드를 지우고 붙여넣기 → 저장.
   3. 배포 → 새 배포 → 유형 선택(톱니바퀴) → 웹 앱 (다음 사용자 인증 정보로 실행: 나 · 액세스 권한이 있는 사용자: 모든 사용자) → 배포.
   4. 액세스 승인 → 계정 → "Google에서 확인하지 않은 앱" → 고급 → …(으)로 이동 → 허용.
   5. 웹 앱 URL (…/exec) 을 붙여넣고 [연결 확인] → [이 PC 자료를 올리고 공유 시작].
9. **휴대폰으로 보기** — 같은 웹 앱 주소 (4판 기능 그대로, 5판에 들어 있음).
   - 비밀번호는 설정 → 휴대폰으로 보기. 요약은 휴대폰 보기를 켠 PC 가 보낸다 (`mobileOn` 은 이 PC 설정).
   - 공유에 참여한 PC (replace · merge) 의 휴대폰 카드에는 "비밀번호는 웹 앱 하나에 하나 — 여기서 바꾸면 모든 휴대폰에서 새 비밀번호" 안내.
10. **화면**
    - 엑셀 · 구글 연동 → 구글 시트 · 드라이브 맨 위 카드 "여러 PC 자료 공유 (구글 드라이브)" (`ERP.cloudCard`).
      - 꺼짐: ① 사장님 PC 순서 · ② 직원 PC 연결 코드 칸 · [연결 확인] → 구글 상태에 맞는 시작 버튼.
      - 켜짐: 마지막으로 맞춤 · 받음 · 보냄 · 시작 · 웹 앱 주소 · [지금 맞추기] · [직원 PC 연결 코드] · [Apps Script 코드 복사] · [공유 끄기] · 기록 · 오류 안내 (`ERP.cloudMsg`).
    - 설정 화면의 짧은 카드 (`ERP.cloudMini`), 왼쪽 아래 "☁ 구글 공유 · 시각" (`/api/versions` 의 `cloud`).
    - 아래 옛 카드 (시트로 보내기 · 가져오기) 는 보기용으로 그대로. 옛 판 안내는 "설치 폴더의 google/Code.gs" 대신 [Apps Script 코드 복사].
11. **설치형** — `cloudsync.js` · `google/**` 를 app.asar 에 넣는다 (package.json `build.files`). GitHub Actions "자동 업데이트 시험 (Windows)" 은 `cloudsync.js` 가 바뀌어도 돈다.
12. **구글 시트 = 공유 자료 보기 (1.13.2, Code.gs 6판)** — Apps Script 를 만든 그 구글 시트에 표마다 탭.
    - 탭 이름 · 머리글 = ERP 화면 (schema.js `ERP.TABLES` 의 한국어 `ko`, 열 순서도 같음). 서버가 schema.js 를 읽어 (`server.js` `loadLayouts`) 보낼 때 표마다 `sheet: {title, ord, cols}` 를 같이 보낸다 → 스크립트 속성 `L_<표>` (바뀔 때만).
    - 화면에 없는 칸은 칸 이름 그대로 뒤에, 맨 끝 "ID (ERP)" (`_id`). `_` 로 시작하는 칸 (`_ex` 등) 은 뺀다. 레이아웃이 없는 표 (5판 ERP · 화면에 없는 표) 는 표 이름 탭 · 칸 이름 머리글.
    - 서식: 빈칸이 아닌 값이 모두 숫자 · 참거짓인 열만 General, 나머지는 텍스트 (@) — 0414210300 · 523034E200 · 2026-10-22 가 숫자 · 날짜로 바뀌지 않게 (2판 규칙과 같음). `=` 로 시작하는 글자는 앞에 `'` 를 붙여 수식 (IMPORTDATA 등 — 시트가 바깥 주소로 자료를 보낼 수 있음) 이 되지 않게.
    - 맨 앞 "ERP 자료 안내" 탭: 표 · 행 수 · 마지막 저장 (구글) · 보낸 PC (`pc` = os.hostname) · 이 시트 (최신 · 갱신 대기 · 오류) · ERP 이름. 처음 한 번 "제목 없는 스프레드시트" → "ColorPencil ERP 공유 자료", 빈 시트1 은 지운다.
    - 탭은 "경고만" 보호. 시트에서 고친 것은 ERP 에 들어가지 않고 다음 갱신 때 덮어쓴다 (자료를 고치는 곳은 ERP).
    - **저장 (`cloud_put`) 과 시트 쓰기 (`cloud_sheet`) 는 따로** — 저장 응답 · 30초 판 · 끄기 전 보내기는 시트를 기다리지 않는다 (생산 일보 2만 행은 시트 쓰기에 수십 초). ERP 는 시트 갱신을 주고받기 (`exclusive`) 밖에서 부른다.
      - 이 PC 가 보낸 뒤 20초 (`sheet`) — 그 사이 저장은 모아서 한 번 (잇따라 저장해도 20초마다 한 번).
      - 다른 PC 가 보내고 시트를 못 바꿈 (그 PC 의 ERP 가 바로 꺼짐 등): `cloud_info` 의 `sv` (시트에 쓴 번호) < `v` 이고 저장한 지 1분 (`sheetLag`) 이 지났으면 이 PC 가 대신.
      - [구글 시트 다시 쓰기] (`POST /api/cloud/sheet`) — 모든 표 (`all`), 바로. 처음 올린 뒤 (`upload` · `overwrite`) 는 2초.
      - ERP 요청이 실패하면 (인터넷 등) 1분 · 2분 … 30분 뒤 다시. 자료 공유는 그대로.
    - **구글 쪽** (`cloud_sheet {all}`): 문서 잠금 — 10초만 기다리고 못 잡으면 `busy` (먼저 온 실행이 새 번호를 다시 본다, ERP 는 20초 뒤 다시). 바뀐 표만 (`SV_<표>` < `T_<표>.v`), 쓰는 동안 새로 저장된 표도 (6번까지), 4분 (`SHEET_BUDGET_`) 넘으면 `more` → ERP 가 이어서 부른다. `all` 은 `SV_` · `SE_` 를 지우고 시작 (도중에 끊겨도 남은 표는 다음 부름에).
    - ERP 탭을 누가 지우면 다음 갱신 때 되살린다. 같은 이름의 다른 탭이 있으면 그 탭은 두고 " (ERP)" 를 붙인다.
    - **오류 표**: 한 표에서 오류 (칸 한도 1천만 등) → 그 표만 건너뛰고 `SE_<표>` = {번호, 오류}. 같은 번호로는 다시 시도하지 않고, 새로 저장되면 다시. 그 탭에는 까닭 한 줄. 화면 "시트에 쓰지 못한 표".
    - **5판으로 배포한 채**면 `cloud_sheet` 를 부르지 않고 카드에 "6판" 안내 (공유는 그대로). 6판으로 바꾸면 밀린 표를 갱신. 시트 없이 만든 스크립트는 `sheet: false` → 부르지 않고 안내.
    - 상태 `GET /api/cloud` 의 `sheet`: {has, url, name, ver, busy, queued, at, code, error, lag, errs}. 1.13.1 까지 연결한 PC 는 `cloud_info` 의 `sheet` (주소) 로 채운다.
    - 화면: 공유 카드의 "구글 시트 (표 보기)" — 상태 칩 (최신 · 갱신 중 · 갱신 대기 n표 · 일부 표 오류 · 확인 중) · 시트 이름 링크 (바깥 브라우저) · 이 PC 가 마지막으로 갱신 · [구글 시트 다시 쓰기] · 안내. 연결 확인이 5판이면 "6판으로 바꾸세요", 결과 창에 "표마다 탭이 생깁니다".

### 3. 서버 API (`server.js`)
- `GET /api/cloud` — 상태 (on · mode · since · lastOk · lastGot · lastSent · code · error · conflicts · shrink · log · pending · local). 누구나.
- `POST /api/cloud/sync` — 지금 맞추기 → 상태. 누구나.
- 이 PC 만 (다른 PC 브라우저 403): `POST /api/cloud/check` {url, token} · `preview` {url, token, nat} · `connect` {url, token, mode, nat} · `off` · `code` {token}.
- `GET /api/versions` 에 `cloud` (짧은 상태). `start()` 의 반환에 `cloud` (electron 이 `flush` · `pending`).
- `POST /api/cloud/sheet` (1.13.2) — 구글 시트 모든 탭 다시 쓰기 (시작만 하고 바로) → 상태. 누구나 (지금 맞추기와 같음). 공유 꺼짐 `OFF` · 시트 없는 스크립트 `NO_SHEET` · 5판 `OLD_SCRIPT` 는 400.
- 시험용 설정: `cloudEvery` (30000) · `cloudPoke` (3000, -1 = 끔) · `cloudFirst` (5000) · `cloudSheet` (20000, -1 = 끔) · `cloudSheetLag` (60000) · `pcName` (os.hostname).
