물어서 정한 것: 기간은 **납기(Checking) 기준** (수주일 기준이 아님 — 9월 전에 받았지만 납기가 10월 이후인 수주는 진행 중으로 남긴다).

### 2. 자료 (이 PC 의 ERP, 2026-10-21 `수주등록.xlsx` 업로드)

### 3. 확정한 것
1. **강제 완료** = PO 줄의 `done_at` (완료 처리일, YYYY-MM-DD). 값이 있으면 포장 실적과 상관없이 그 줄은 완료(`done`). 취소 · 보류 표시가 여전히 이긴다 (기존 규칙).
2. 수주 목록(PO별 보기)의 각 줄 끝에 버튼: 진행 중 PO → **완료**, 강제 완료한 PO → **완료 취소**. 누르면 확인 창 (PO 번호 · "포장 실적과 상관없이 완료" · 되돌리는 법). 상세 칸에도 **완료 처리** / **완료 취소** 버튼과 "완료 처리 (날짜)" 표시.
3. PO 를 완료로 표시하면 그 PO 의 진행 중 줄(완료 · 취소 · 보류가 아닌 줄)에만 `done_at` 을 넣는다. 완료 취소는 `done_at` 을 지운다.
4. 일괄 완료 `C.closeByDue(from, to)`: 납기가 from ~ to 인 진행 중 줄을 완료로 표시하고 업로드 이력에 남긴다 (`kind: 'po_close'`). 이 PC 에서는 2025-01-01 ~ 2026-09-30 으로 한 번 실행.
5. 수주 엑셀을 다시 올려도(기본 upsert) `done_at` 은 남는다 (upsert 는 파일에 없는 칸을 지우지 않음). "전체 교체" 로 올리면 지워진다.
6. AI 비서 수주 도구: 강제 완료 PO 는 남은 세트 0, `marked_done` = 완료 처리일.

### 4. 코드 규칙
- `schema.js` PO 칸 `done_at` (완료 처리일, 날짜). 품번 라인별 보기의 편집 창에서도 보이고 고칠 수 있다.
- `calc.js`: `C.orders` — `if (p.done_at) st = 'done'` (조건 칸 검사 전), 줄에 `forced`. `C.poGroups` — `forced` (진행 줄 중 강제 완료가 있음), `doneAt` (가장 늦은 완료 처리일). `C.closeLines(lines, day)` · `C.reopenLines(lines)` · `C.closeByDue(from, to, note)`.
- `p_orders.js`: `closePo` · `reopenPo` (확인 창 → 저장 → 다시 그림), `doneBtn(o, big)`. 목록의 버튼은 `stopPropagation` (줄 선택이 바뀌지 않음).
- `assistant_tools.js`: `remaining_sets` 는 강제 완료면 0, `marked_done`.

### 5. 지켜야 할 것
- 완료 판단은 그대로 (포장 실적 ≥ 세트). 강제 완료는 사용자가 누른 것만 — 자동으로 넣지 않는다.
- 일괄 완료는 사용자가 기간과 기준(납기 / 수주일)을 정한 뒤에만.
